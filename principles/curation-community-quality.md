# 策展+社区双层质量：用分层替代一刀切

## 是什么

开放平台的质量控制不能一刀切。"全审" = 死（规模化不了），"全放" = 乱（用户不信任）。用双层机制解决：策展层保证质量下限，社区层提供规模和多样性。

策展 = 少数精选，人工审计，质量承诺。社区 = 众人投稿，投票排序，好的升到策展。

## 怎么用

### 四步设计清单

1. **定义策展层标准**：什么质量才算"策展"？具体的、可自动化的检查项，不是"看起来好"
2. **定义升降级规则**：社区 → 策展需要什么？几个投票？什么审计？策展 → 社区（降级）需要什么触发？
3. **默认可见性**：社区内容默认不公开还是有限公开？搜索可见吗？
4. **防止富人更富**：新投稿怎么获得初始曝光？不能让首页 100% 是旧内容

### 关键追问

```
问: "投票机制会不会被刷？"
答: 会。但策展层不靠投票——投票只影响"是否从社区升到策展"，不失影响什么在策展层。策展层是人工门禁，投票只是信号之一，不是全部。
```

## 案例

**版式画廊三层质量体系**：

```
第一圈：策展层（curated）
  现有 45 模板 + 未来人工精选
  品牌套件完整、token 经过审计
  质量承诺——用户可以信任这一层

第二圈：社区层（voted）
  任何人贴 URL → 生长 Agent 萃取 → 自动投稿
  点赞/收藏把好的推上来
  达到阈值 → 升级到策展层

第三圈：草稿层（draft）
  萃取完但未审核
  搜索默认不显示
  作者自己可见 + 可分享链接
```

**不用这个原则之前**：担心开放投稿会污染库，于是在"全审"和"全放"之间摇摆。
**用了之后**：三层各解决不同问题——策展保证信任，社区保证规模，草稿保证安全。

**类比**：代码审查的二分法——人工审核（策展）= 质量门禁，自动化测试（投票）= 规模化筛选。

## 边界

- 双层不是"两个文件夹"——草稿 → 社区 → 策展是三态，每态有不同权限和可见性
- 投票不是唯一升层条件——人工审计权重 > 投票数
- 社区层需要激励机制：为什么有人愿意投稿？曝光 + 署名 + "被策展"的社会资本
- 不适用于小型封闭系统（≤ 50 条目）——小规模人工策展就够了
