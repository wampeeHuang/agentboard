# 抓取边界字段契约：平台元数据别灌进治理字段

## 是什么

任何"外部抓取 → 写入目标库"的管线，抓取层写入前必须先核对目标字段的数据契约（白名单/枚举/类型）。平台原生元数据（hashtags、原始标签）与目标系统的治理字段（聚合维度、受控枚举）语义不同，混写 = 批量污染门禁。

开发者默认"API 给什么就写什么"，但目标库的 `tags` 往往不是开放字段——它有白名单、有语义（聚合维度而非描述）。抓取层把平台话题当 tags 灌入，等于把「内容描述」塞进「受控分类」。

## 怎么用

1. **写入前读 schema**：确认目标字段是开放字段还是白名单字段，枚举有哪些
2. **平台原生元数据 → 独立保真字段或正文**，不进治理字段
3. **治理字段只写白名单项**，缺失映射宁可留空不硬塞
4. **门禁报批量违规 → 先查抓取层映射**，不是逐个擦数据；剥离前先验证数据在别处有副本（无损优先）
