# 策展标注必须可编辑；删除=低频逃生门：二次确认 + 回退到可再操作态，不留隐藏名单

## 是什么

任何人工叠加在数据上的标注系统（命令注解、分类、中文名、说明），标注一旦写入就**锁死**不可改 = 落盘限死：用户发现标错也无法纠正，整个标注价值崩塌。同理，删除如果做成一击即走、还进"永久隐藏名单"，就是把低频逃生门变成了不可逆的副作用。

规则：
1. **标注必须可编辑**——写入后有编辑入口，预填当前值，提交走同一 upsert 通道。没有编辑 = 没有标注，只有一次性输入。
2. **删除是逃生门不是主流程**——低频、可逆。默认语义是"回退到可再操作态"（去掉标注回未标注桶），不是"抹掉数据"。
3. **删除要二次确认**——首击进入确认态（文本变「确认删除？」），二击才执行。防误触。
4. **不留永久隐藏名单**——让用户操作产生"看不见的持久副作用"（dismissed 名单、隐藏列表）的设计都要先问：副作用可逆吗？用户看得见吗？删除对象源里还在，应能再标回来。

## 怎么用

1. **标注入口自带编辑**：每次渲染标注对象时，带「编辑」按钮，弹窗预填当前分类/名称/说明；身份字段（标注键，如命令名）只读——身份不可改，内容全可改。
2. **删除语义分两档**：
   - 源里还在（提取命中）→ 删 = 去掉标注，对象回未标注桶，随时可再标
   - 源里已无（灰命令）→ 删 = 彻底消失（对象本体已不存在，无回退目标）
3. **二次确认的 UI 细节**：确认态不能让布局重排——按钮固定 min-width，文案从「删除」变「确认删除？」同宽；超时自动复位，避免卡在确认态。
4. **拒绝任何隐藏名单**：删除成功即结束，不写 dismissed/blacklist。下次扫描对象回来就是未标注态，用户重新决策。

## 案例

agentboard 命令 tab：标注斜杠命令（分类/中文名/说明）后，一度只有标注没有编辑——用户指出"没有编辑 = 落盘限死"。删除当时做成一击 + 永久 dismissed 名单——用户否掉："删掉它也不要进入列表吧。一般其实不会去做这个删除操作的。只是给自己一个操作空间而已"。

**用之前**：标注一击写入不可改；删除一击执行进隐藏名单——标错改不了、删错找不回。
**用之后**：编辑弹窗预填可改（命令名只读）；删除首击变「确认删除？」红闪 3 秒二击执行；删 = 回未标注桶（源在可再标），灰命令删 = 消失；无隐藏名单。

## 边界

- 身份字段（标注键）不可编辑只适用于"身份唯一"场景。身份本身可迁移的系统（如重命名命令），身份也要可改——判定标准是"改了这个会不会破坏键的唯一性"。
- 二次确认适用于破坏性删除。非破坏性操作（编辑、改分类）不需要二次确认——确认弹窗用多了会麻木，只在不可逆处加。
- "删除=回退"要求对象源还在。对象源已删（灰命令），回退无目标，删就是删——边界明确，两档语义不混淆。
