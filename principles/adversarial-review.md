# 对抗性审查：如果我是竞品，怎么杀掉这个项目

## 是什么

站在竞品角度，用最低成本、最致命的方式摧毁自己的方案。找到致命弱点 → 反向加固防线。

这不是悲观——是"如果不主动找自己的死法，竞品会替你找"。

## 怎么用

### 三步检查清单

1. **列出杀手**：谁能杀？用最低成本。Vercel 能杀 = 加一行 shadcn token 支持。Anthropic 能杀 = Claude 内置设计 token。
2. **评估致命程度**：杀了会怎样？用户全部流失？还是只丢一部分？护城河多深？
3. **反推防线**：对每个杀手，问"有什么是竞品杀不了/不愿做的？"——那就是真正的护城河

### 关键追问

```
杀法: "开源社区爬了 10 万网站的 token → 开源库"
致命吗？中等。数据护城河会消失，但策展质量不会。
防线: 策展质量（机器能爬，不能判断好坏）+ 使用语境（爬虫拿不到设计决策逻辑）+ 验证闭环（能爬 token，不能证明 token 好用）
```

## 案例

**版式画廊的对抗性审查**：

| 杀法 | 谁可能做 | 致命程度 | 防线 |
|------|---------|---------|------|
| "Claude 内置设计 token" | Anthropic | 直接灭 | 品牌多样性——Claude 内置的是通用 token，画廊的是具体品牌 DNA |
| "shadcn/ui 注册表加品牌 token 支持" | Vercel | 吃掉最大用户群 | 框架无关——不绑 Next.js/Tailwind |
| "Tailwind 5.0 内置设计系统导入" | Tailwind 团队 | 消灭"框架无关"卖点 | 策展质量——自动导入 vs 人类审计 |
| "开源社区爬了 10 万网站 token" | 某个 GitHub repo | 数据护城河消失 | **使用语境 + 验证闭环**——这两样爬虫拿不到 |

**结论**：真正的护城河不是数据量，是策展质量 + 使用语境 + 验证闭环。

## 边界

- 对手指大公司时，要判断"他们有意愿吗"——Anthropic 能杀但不一定想做
- 不要陷入"什么都能杀"的虚无主义——杀法的成本不一样，低成本杀法才需要担心
- 审查完必须产出"防线清单"，不能只列不防
