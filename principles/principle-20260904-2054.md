# 认证恢复是窄权限本地桥接，不是人工秘密交接

## 是什么

当自动化服务需要复用用户的浏览器登录会话时，认证恢复应设计成一个范围最小、仅到本机的桥接能力，而不是让人反复复制 Cookie、token 或其他秘密。秘密的流向、保存期限和消费者必须可约束、可观察。

## 怎么用

1. 先确认最终服务真正需要哪些认证字段，别把作者身份、会话参数和 Cookie 混成一个 token。
2. 桥接端仅拥有目标域名权限；接收端仅为 loopback 地址；不设公网转发。
3. 默认按用户动作同步，后续再由明确的失效信号触发恢复请求。
4. 不在扩展存储、日志、面板或 agent 对话中显示秘密。
5. 在最终执行工作台展示非秘密健康状态，并用真实请求验收，而不是只看“已保存”。

## 案例

微信抓取服务无法稳定读取 Chrome Cookie 库。会话桥扩展只读 `mp.weixin.qq.com` 当前会话，且只 POST 到 `127.0.0.1:3095`；同步后服务端 `check-cred` 返回凭证有效。Agentboard 将它登记为“社媒数据抓取”的认证依赖，而不是独立抓取工具。

## 边界

这不是绕过登录、风控或平台权限的方案。若平台有官方 OAuth/refresh token，应优先采用官方授权流；若需要跨机器/云端同步，则必须另行设计密钥管理、用户授权与审计，不能把本机 bridge 直接外推。
