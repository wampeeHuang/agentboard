# 原则库宪法

> 一条原则「值不值得收、怎么写、写什么、怎么养」的唯一裁决。
> 原则是决策框架，与经验日志（`tips/`）是两物种——本宪法只管原则库。

---

## 〇、使用流程（先读这节）

**写入时**，按序走完四步，任何一步不过就停：

```
1. 准入 → 四问全过才收（不是"tip"的拆装）
2. 分类 → 这条原则指导哪一种决策（六类互斥）
3. 套格式 → 面板「+ 新增原则」表单：是什么 / 怎么用 / 案例 / 边界
4. 查不收录 → 别收进不该收的东西
```

**决策时**（原则库的本职）：
```
做决定前 → 查原则匹配 → 读边界（什么时候不适用）→ 应用
```

**维护时**：演化 · 过期即删 · 合并优先 · 超 30 触发锐度审查 · 不凑数。

---

## 一、原则 vs Tip

Tip 是踩坑日志。原则是决策框架。Tip 告诉你"别踩这个坑"，原则告诉你"怎么想到这里有坑"。

- **回答什么** — Tip：为什么X会这样？（诊断）｜原则：面对Y该怎么做决定？（决策）
- **触发时机** — Tip：出问题后查阅｜原则：做决定前主动调用
- **生命周期** — Tip：API 变了就过期｜原则：思维框架，被更通用的覆盖才淘汰
- **数量预期** — Tip：50-100 条｜原则：目标 20-30 条核心原则，不设硬上限

---

## 二、准入标准（四问）

写入前逐条过。四条全过才落盘，一条不过就放弃。

- **可复现吗** — 换了场景、换了项目、换了领域，仍然能用
  - 不通过示例：「这次用蓝色好看」——一次性审美判断
- **可操作吗** — 含有具体检查步骤或决策框架，不是纯标语
  - 不通过示例：「保持简单」——没有行动指引
- **反直觉吗** — 说出来正常人第一反应是"不对吧"——那才对
  - 不通过示例：「代码要写注释」——人人都知道
- **跨领域吗** — 不绑死在一个项目/技术栈/语言上
  - 不通过示例：「React组件用hooks」——只适用于React

### 优先级速判

```
换了三个项目仍能用 → 必收
说出来别人愣一下然后点头 → 必收
能直接生成检查清单 → 必收
只有本领域适用 → 不收
纯鸡汤/标语 → 不收
```

## 三、分类（六类）

同一维度：**这条原则指导哪一种决策**。一条原则只归一类。

- `review` **审查** — 怎么审查一个方案？提供系统性多角度审查框架
  - 示例：第一性原理审查、对抗性审查
- `design` **设计** — 怎么做一个设计决策？指导具体设计选择的原则
  - 示例：换行即设计
- `architecture` **架构** — 怎么做一个架构决策？系统级结构选择的原则
  - 示例：一源多端、策展+社区
- `governance` **治理** — 怎么定治理制度？治理机制/巡检门禁的边界设计
  - 示例：制度必须有执行验证
- `engineering` **工程** — 怎么做工程决策？工程接口/契约的边界设定
  - 示例：爬取边界字段契约
- `communication` **沟通** — 怎么协作沟通？协作/沟通中的行为边界
  - 示例：用户选的方向不转卖

互斥检验：一条原则不可能同时主要回答两种决策——归入最能指导的那一类。

## 四、格式

### 文件结构

落盘文件由服务端自动生成，**不用手写 markdown**。写入走面板「+ 新增原则」表单：

- 标题 → 表单「标题」字段（文件名 kebab-case 自动生成）
- type → 表单「类型」下拉
- 是什么 / 怎么用 / 案例 / 边界 → 表单四个分区字段
- date / source → 表单头字段（可选）

手写文件时字段名对齐表单，见 §四 格式约束。

### 格式约束

- type 必填
- 一个文件一个原则。不要合集
- 120 行以内。超过说明拆得不够细
- 中文为主，代码/变量名/专有名词英文
- 文件名用 kebab-case，语义化

## 五、边界（不收录清单）

- **行业常识** — 任何一个从业者都知道的 → 不收
- **技术规范** — 「用 HTTPS 不用 HTTP」——安全常识 → 不收
- **个人偏好** — 「我喜欢用 tab 不用 space」 → 不收
- **特定工具约束** — 「Git 比 SVN 好」——不是思维框架 → 不收
- **CLAUDE.md 已覆盖** — 宪法已有 → 不收
- **踩坑日志** — 是「为什么X会这样」不是「怎么决定」 → 放 `tips/`

---

## 六、维护

- **原则可以演化。** 发现更好的表述/更大的适用范围 → 更新原文，标注修订日期
- **过期即删。** 被更通用的原则覆盖了 → 删除
- **合并优先于新增。** 新原则能归入已有原则的子规则 → 合并
- **数量是信号，不是门禁。** 超过 30 条触发一轮锐度审查：合并重复、淘汰最弱。审查完继续收——原则不设硬上限，思维框架没有 API 漂移，真正的闸是 §二 四问
- **不凑数。** 5 条高质量 > 30 条流水账

---

*本宪法约束原则库的写入和维护。每次想收一条时先读本文件。*
