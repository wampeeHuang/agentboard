# 表单承接标准：写入表单结构即写入标准本身

## 是什么

当一份「写入标准」（格式规范，如日志分区分节、申报表字段）比一个普通输入框复杂时，写入表单应该按标准的分区字段**动态渲染**——表单的结构就是标准本身。用户按表单填出来的每一条天然符合标准，而不是一个裸 textarea 对着复杂标准空转。

标准与表单是同一件事的两面：标准定义「合法的成品长什么样」，表单把标准转译成「可填写的结构」。表单承接标准，不是表单对照标准。

## 怎么用

1. **把标准拆成可填分区**：标准正文由哪些 `##` 分区构成（现象/根因/修复/预防…），每个分区是一个字段。
2. **表单按类型动态渲染字段**：不同类型有不同的分区集，选类型即换字段集；有 frontmatter 元数据（如工具名、场景）就单列输入。
3. **保存 = 按标准拼装**：前端把分区字段拼成 `# 标题` + `## 分区` 正文 + frontmatter，后端只落盘。
4. **编辑 = 反向解析回填**：拉取成品 → 解析 frontmatter 与 `##` 章节 → 回填各分区字段。

## 案例

经验日志宪法 §三 格式 vs 写入表单：

| 标准 | 表单 |
|------|------|
| diagnosis/method/fact/feedback → 现象/根因/修复(步骤)/预防 四分区 | 类型下拉 onchange 换四分区 textarea |
| capability → 能力/为什么只能用这个/速查 | capability 类渲染三分区 + 工具/场景两个 frontmatter 输入 |

保存时按所选类型拼装分区正文，编辑时解析回填。用户不用读标准也知道怎么写出合规条目——标准的内化被表单承担了。

## 边界

- 仅当标准结构明确可分（分区/字段清晰）时适用；纯自由文本标准不需要，别为它发明结构。
- 表单是标准的投影，标准改了表单跟着改——先改标准文档，再改表单字段集。
- 不适用于字段不可穷举的自由输入；如果标准本身模糊（没有明确分区），先定标准再做表单。
