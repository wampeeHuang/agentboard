# 名实脱钩是腐化信号：标识符名≠真实值，审计按值不按名
type: review
date: 2026-08-26
source: vivi-design-system 换皮后 5 处类名/变量名与颜色值脱钩，一次按值扫描全数暴露

## 是什么

标识符（变量名、类名、字段名、常量名、参数名）与它承载的真实值或行为分离时，系统已经腐化。人默认相信名字——"`.hl-yellow` 一定是黄色"——而真值在定义处。发现名实脱钩，等于收到系统性腐化信号，立即按值审计，别按名推断。

## 怎么用

触发场景：换皮、改版、重构、数据迁移、批量替换后。三步：

1. **发现信号**：任一标识符名与值矛盾（类名说黄、值是墨；变量名说 blue、值是绿）——不管看起来多"合理"，停止按名推断。
2. **按值扫描**：列出真相契约的全部值（品牌色/字段枚举/常量定义），grep 每个值的出现位置，反向归类。1 处脱钩是巧合，≥3 处同类 = 系统性腐化，直接修到真相源。
3. **区分两种脱钩**：
   - 名旧值新（如 `--blue` 名旧、值已是品牌绿）→ 无害但需改名或标记，防未来误用
   - 名对值错 / 名新值旧（类名 `-yellow` 值墨）→ 真 bug，立即修值到契约

## 案例

vivi-design-system 换皮后按类名排查"黄色为什么没出现"——每个类名都叫 yellow，全"对"了，但实渲染绿墨白、黄缺席。改为按值扫描品牌色 `#262B27`，暴露 5 处：`--yellow: #262B27`（名黄值墨）、`.hl-yellow` 荧光笔墨底、`.card-pill--yellow` 墨背景、`--blue` 名蓝值绿、`.cool-btn-yellow`。

**用之前**：信类名 → 逐个文件看 → 都觉得"对" → 找不到 bug。
**用之后**：按契约色值 grep → 5 处脱钩一次曝光 → 修值 → 黄绿白真实呈现。

## 边界

- 名旧值新如果值正确且渲染正常，改名是低优先清理项——先修值错的，改名放最后
- 纯命名风格偏好（camelCase vs snake_case）不属此类，那是风格不是脱钩
- 契约/真相源本身要可信：按值审计的前提是"值"有唯一真相源（brand-dna、schema、manifest），没有就先把真相源立起来
