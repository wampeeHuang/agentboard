# 知识资产必须纳入版本控制：可重建的才可忽略

## 是什么
判断一个目录该不该进 git，看它的**不可重建性**：可重建的运行数据（日志、缓存、快照）可以忽略；不可重建的知识资产（经验、文档、规则、代码、配置）必须入库。知识资产的价值恰恰在"可回溯、可恢复、有历史"——被忽略 = 失去这些。

## 怎么用
1. 建立/审计任何项目时，逐条检查 .gitignore：每一条忽略都要能回答"为什么"，且不涵盖知识资产
2. 核心知识库（tips、docs、rules、principles）默认入库，除非有明确的隐私/体积理由
3. 用门禁兜底：tree-drift / inspection 之类的审计要能发现"知识目录被忽略"这类隐性债

## 案例
~/.agentboard 审计发现 `tips/`（445 条经验）在 .gitignore 里——无历史、不可回滚。修复：移除忽略行 → `git add tips/` → 一次性提交 448 个文件。此后每条经验随提交入库，历史即资产。

## 边界
- 本机个性化数据（tools/ 的端口/路径/manifest）不入主库是合理的——它有嵌套 git 或备份兜底
- 含隐私/密钥的知识库可以私有仓库，但不能无版本控制
- "暂不提交"是临时状态，不是忽略规则——遗忘即丢失
