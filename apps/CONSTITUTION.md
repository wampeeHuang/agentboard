# 网站注册表宪法 · 公网应用

> 一条应用记录「值不值得收、怎么写、写什么、怎么养」的唯一裁决。
> 本宪法以网站注册表（`~/.agentboard/apps/`）为单位。

---

## 〇、使用流程（先读这节）

**写入时**，按序走完三步，任何一步不过就停：

```
1. 准入 → 二问全过才落盘
2. 填字段 → 面板「+ 添加网站」表单（id/url 由域名派生）
3. 查不写入 → 别写进不该进的东西（见 §四）
```

**维护时**：过期即下线 · 发现即修 · 不凑数。

---

## 一、准入标准（二问）

- **有公网入口吗** — 有真实可访问 URL（`https://…`）才算
  - 不通过示例：只有 localhost 内网服务 → 那是 `tools/` 工具架，不是公网应用
- **持续有价值吗** — 值得保留在架上，不是一次性临时页
  - 不通过示例：临时演示页、测试域名、随手建的验证站

---

## 二、格式

一条应用 = 一个 `{id}.json`，`id` = 域名。字段由 `lib/apps-schema.js` 校验（未知字段不拦，agent 可扩展）。

| 字段 | 必填 | 来源 | 说明 |
|------|------|------|------|
| `id` | ✓ | 派生 | 域名，即文件名 |
| `name` | ✓ | 表单 | 显示名称 |
| `url` | ✓ | 派生 | `https://{id}` |
| `description` | ✓ | 表单 | 一句话说明 |
| `status` | ✓ | 自动 | `live` |
| `host` | ✓ | 表单 | 托管链路 |
| `devTool` | — | 表单 | 本地开发服务（工具卡 id，地址渲染时从工具端口派生；`localDev` 为旧卡兼容字段） |
| `agentNote` | — | 表单 | AI agent 使用注意事项 |
| `order` | — | 拖拽 | 排序权重，面板拖拽写（`/api/apps/reorder`），不手填 |
| `endpoints` | — | agent | 端点映射对象（llms.txt / openapi.json 等） |
| `logo` | — | agent | logo URL |

---

## 三、边界（不写入清单）

- **本地服务** — 无公网 URL → 放 `tools/` 工具架，不是 apps
- **双栖实体（本地有进程 + 公网已部署）** — 两面分家，不复制：公网面记这里（网站身份：名字/公网地址/托管/站点状态），工具面记 `tools/`（端口/启停/运行时/Agent 笔记，manifest 里 `publicUrl` 字段指向本站）。只有「名字」两处出现（几乎不变，漂移风险可忽略），其余字段各有一个家。
- **未上线** — 还没部署、域名不可访问 → 不上架
- **操作历史** — 谁在什么时候改了什么 → 放 `state/call-log.jsonl`

---

## 四、维护

- **过期即下线。** 域名失效 / 服务关闭 → 删 `{id}.json`
- **发现即修。** 读到信息有错 → 立刻改，不等下次
- **不凑数。** 5 条高质量 > 30 条流水账

---

*本宪法约束网站注册表的写入和维护。每次想记一条时先读本文件。*
