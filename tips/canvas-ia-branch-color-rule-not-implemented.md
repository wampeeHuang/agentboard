# 规则文档承诺的配色没实现，而门禁只校验"已着色的合规"

## 现象

用 `canvas-ia` 技能生成一张 373 节点的信息架构画布，自带门禁 `verify_grammar.py --strict` 报 **16/16 通过**，于是当作合格交付。

用户看了一眼说：「全是灰色的，什么也看不出来。」

统计后确认：373 个节点里 **只有 5 个有色，367 个全灰**。

## 根因

两层问题叠加，缺一层都发现不了：

**第一层：实现没跟上规则。** 技能自己的 `references/grammar.md` 第 145-183 行把 v3 配色规则写得很清楚——「分支头＝任何有子节点的节点；同一父下 ≥2 个分支头 → 按序从 7 色板取色；一支的整棵子树继承这支的颜色，边色＝下游最近的分支头颜色」。但 `scripts/canvas_grammar.py` 里 `emit()` 只实现到「顶层一级轴各一色」（`axis_color` 参数），**分支轮转配色从来没写**。

**第二层：门禁是合规性检查，不是覆盖率检查。** `verify_grammar.py` 那 16 项里与颜色有关的是「颜色取自声明的调色板」「叶子值一律无色」「同层相邻兄弟不重色」——**全部在问"已经上了色的那些对不对"，从不问"该上色的有没有上"**。所以 0 着色和满着色都是 16/16 通过。

## 修复/步骤

1. 给 `make_canvas.py` 补 `apply_branch_colors()`：
   - 用**节点 id**（不是文字）建父子图——画布里同名轴块很多，按文字判父子必错
   - 逐父节点取子节点，按 y 排序，筛出其中有子节点的（＝分支头）
   - ≥2 个分支头才着色，按序轮转 7 色板；<2 个不着色（避免把独苗显得特殊）
   - 边色＝沿 `toNode` 向上找第一个有色祖先
2. **叶子保持无色** —— 我先写了「整棵子树全染色」的版本，被 `grammar.md` 自己的「叶子值一律无色」一条挡下。颜色是写在**连线上**的，「一支的范围」靠边色看出来，不是靠把叶子染色。
3. 改外部技能前先备份原文件（本例备份到 `_runtime/skill-backup/`），改完跑语法检查 + 自带门禁双验。

## 预防

- **门禁要同时回答两个问题**：该有的都有了？已有的都合规？只答后者会出现"空转通过"。
- 覆盖率类断言最好能给出**分母**：本例正确的输出应是「着色节点 26/26 分支头，叶子 346 个按规则无色」，而不只是「16/16 通过」。
- **规则文档与实现分居两地时，要显式验证一次"文档承诺的行为是否真的发生"**。本例规则文档写得很细，反而让人误以为实现也是完整的。
- 交付前做一次**最朴素的用户视角检查**：这张图"能不能一眼看出结构"。门禁绿灯不等于人看得懂。
