# 领域分离用物理目录而非字段：写路径强制 + 读取隔离 + 零遗忘失效

## 事实
DSH 经验日志的领域分离（通用 / dsh / cron）最终采用**物理子目录**而非 frontmatter 字段：

```
~/.agentboard/tips/          ← 通用（根目录）
       ├── dsh/              ← DSH 专属
       └── cron/             ← 调度中心专属
```

配套机制：前端按文件路径前缀自动归属标签页（`dsh/xxx.md` → DSH 标签）；POST 按 domain 写对应目录；`file` 字段带子目录前缀。

## 为什么必须用物理目录（而非字段）
| 维度 | 字段方案（domain: dsh） | 物理目录方案 |
|---|---|---|
| 写入 | 每次都要判断"去掉 DSH 还成立吗"，忘标 = 静默混入 | 文件在哪个目录就是哪个域，**写路径天然强制** |
| 读取 | 每个读者都要记得加 filter | 读目录即隔离（claude 读根目录天然看不到 dsh/） |
| 遗忘失效 | 存在（忘标无报错） | **不存在** |
| 存量迁移 | 需要回填 | 零迁移（根目录 = 通用，只有新增子目录） |

判据（依附性测试）依然保留用于**写前分类**："去掉 DSH 这条经验还成立吗？"——但它的失败模式被物理目录兜底了：即使判错，文件位置也决定了归属。

## 案例
8 条 DSH 经验移入 `tips/dsh/`（去前缀改名）后，面板 DSH 标签自动显示 7 条、API `?domain=dsh` 精确返回——零额外配置，全靠路径前缀推导。

## 适用
任何"某个生态的知识/资产需要从通用池剥离"的场景：独立口 = 建物理目录 + schema 枚举 + 前端按路径归属，三件套缺一不可。
