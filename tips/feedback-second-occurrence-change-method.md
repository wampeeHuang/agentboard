# 同一条反馈第二次出现就换方法，不要再调参数

## 现象

用户对同一张产物连续给五轮反馈，**每轮指向同一类问题**，我每轮都在原方案上调参数
（改判据 → 收紧判据 → 抹文字 → 压缩间距 → 第三次改公式），五轮没解决，用户收回自己做。
期间每一次中间构建都直接写进**用户正在编辑的那个文件**，他每轮都要手工重看一次。

## 根因

三层：

1. **把几何约束当参数问题。** 用户要的「同层节点相互靠近」和「层级 = 列」在纵向树里**互斥**：
   同层兄弟的间隔**必然**等于前一个兄弟整棵子树的跨度（实测 2260px / 10660px）。
   方向本身不可能，加多少力都没用。
2. **判据自己写错就报假绿。** 第一轮的判据漏了一种情形（没有入边的那些节点），
   于是"修好了"是假的，用户第二轮就看到了。
3. **拿用户的资产当草稿纸。** 中间态（含被门禁拒绝的那些）全写进用户路径，
   而用户自己也在改同一个文件 → 变成"他改好→我重排→他再改"的对抗。

## 修复/步骤

**触发条件：同一条反馈第二次出现。此时不许直接改代码。**

1. **写一句"为什么上一版不满足"**（不是"再试试"）。写不出来说明还没理解问题。
2. **判断这是参数问题还是约束冲突。** 问自己：这两条要求能同时满足吗？
   如果不能，**列出来让用户选**（每条方案写清代价），不要挑一条实现、假装另一条也满足。
3. **先量用户已经改过什么。** 他的坐标/结构改动是**判据**，不是噪声 ——
   diff 出来、量出他用的常量（如列距），当成新方案的目标。
4. **产物迭代只落临时路径**，过完门禁和全部判据才换入用户路径；换入前备份，**备份留多代**。
5. **写盘前自检"除目标字段外零变动"**，有其它字段变动就整批拒绝写入。

## 预防

- 同一产物连续三轮同类返工 = 立即从"调参"切换到"对齐约束"。
- 门禁/判据每次修改都要能**反向证伪**（人为破坏后必须报红），否则那份"通过"没有意义。
- 用户的文件在被改期间，**它是用户的**；你的中间态不属于那里。
