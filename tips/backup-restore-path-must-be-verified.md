# 备份声明≠备份能力，恢复路径必须实测一次

文档白纸黑字说"git clone 能恢复工具注册表"，实际 `tools/` 在 `.gitignore` — git 里根本没有。文档从没被实测过，直到出事才知道是假的。

## 现象

18 个 manifest 因文本替换事故全部 JSON 截断。走恢复时发现：git 历史、备份、悬空 blob 全查过 — tools/ 在 .gitignore，任何 git 恢复方式都拿不回 manifests。

## 根因

备份/恢复文档写的是"声明"不是"实现"。repo-spec 说"含工具注册表 tools/"但从未实际 clone 验证过。声明与实现漂移，漂移时间越长恢复代价越大。

## 修复/步骤

写备份/恢复文档后必须实测一次完整恢复路径：
1. `git clone` 到全新目录
2. 跑起来（`node server.js`）
3. 确认关键数据在（tools/、tips/、apps/）
4. 不在 → 修正备份方案或文档，直到跑通

## 预防

- 文档说"能恢复"不是完成，跑通了才是
- 恢复快照（即使不完整）是运行时数据丢失时的救命稻草 — 前提是快照**持续存在**且**字段完整**
- git 忽略的目录要有备用恢复源（如 `_runtime/` 下的 scan 输出快照）
