# 用户提出的方案，先问"它解决什么问题？这个问题真的存在吗？"

## 现象

用户提出一个技术方案（"HTML 如何实时联动飞书参数"），Agent 直接进入方案评估模式（"TOML vs JSON vs 实时 API"），而不是先追问问题本身。

## 步骤

1. **听到方案提议时，先不评价方案好不好。**
2. **问："这个方案解决什么问题？"**
3. **追问："这个问题现在真的发生了吗？还是假设会发生的？"**
4. **如果问题是假设的 → 伪需求，不建。**
5. **如果问题是真实的 → 追问："有没有比这个方案更简单的方式？"**

## 为什么

用户习惯用方案语言表达需求（"我要一个实时联动"），但方案背后的问题可能根本不存在，或者有更简单的解法。Agent 默认跳过问题验证直接评估方案，等于对着一个不存在的靶子射箭。

本案例：用户真正需要的是"参数改了我知道、结果能追溯到用了哪版参数"——一个参数版本戳就能解决，不需要实时联动。
