# 归档搬迁要四步走：复制 → 校验 → 改引用 → 校验 → 才删源

## 现象

按摄入管线要把 175 篇 raw 原文从暂存目录 `raw/文章/<项目>/` 移到归档目录 `raw/已消化/`（扁平 + 前缀命名），同时 wiki 里有 **430 处引用**指向旧路径（正文脚注 101 处 + 画布节点文本 329 处）。

这类搬迁有两种典型失败：搬完发现引用全断（要改 430 处才发现），或者删完源才发现漏搬了几个文件（且 `raw/` 在 `.gitignore` 里，**没有 git 历史可恢复**）。

## 根因

风险集中在"删源"这个不可逆动作上，而它偏偏最容易被放在最前面做（先删后建感觉更干净）。raw 层是 `.gitignore` 覆盖的（该库注释写明 too large for git 49GB+），所以删掉就是真删掉。

## 修复/步骤

固定成五步，每步都有可验证的产出：

1. **复制**（不删源）：逐个文件复制，**复制后立刻比对字节数**，不一致即中止。
2. **改引用**：对目标文件做纯文本替换；画布用「手术式」改法——只改 `text` 字段，改完逐节点比对证明**坐标、尺寸、颜色、连线数一个都没动**（画布是 JSON，重建会覆盖用户手工调整）。
3. **校验**（删源前的闸门）：两个都必须为 0——
   - 旧路径残留数 == 0
   - 新路径引用中**解析失败数 == 0**（`existsSync` 逐个验）
4. **删源**：只有第 3 步两个都 0 才执行。
5. **复跑门禁 + 提交**：来源链检查（逐条验 frontmatter `source` 是 URL、正文有「原始来源」标记、文件存在）通过后提交。

## 预防

- **校验器自己要先被校验。** 本例第一版校验脚本写了 `replace(/__/g,'/')` 去还原文件名，然后在正则里用 `[^\s]+?\.md` 匹配——把文件名里的双下划线匹配错了，报出 156 处"假失败"。**校验脚本报失败时，先确认失败是真的**，否则会按错误信号去"修"本来正确的东西。
- **搬迁中发现"目标文件名不存在"，先怀疑映射规则而不是文件缺失。** 本例真正的失败原因是：某批文档从未抽取过（画布却按路径写了链接），补抽取才解决——而不是去改引用。
- **引用数即风险面**，动手前先数一遍（本例 430 处），数量级决定要不要写脚本而不是手改。
- 搬迁脚本、期望值、中间产物都放 `_runtime/`，不落进内容目录。
