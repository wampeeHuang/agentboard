# 换行不是美化，是信息结构

## 现象
Agent 将多个独立事实塞进一个段落——标准地位、治理结构、效果数据全挤在四行里。用户："不换行吗？看着好费劲。换行也是信息表述的一部分。"

## 根因
Agent 把换行当排版（可选的视觉优化），不当信息架构（必须的语义分隔）。一个段落塞多个独立断言 → 读者被迫自己切分 → 认知负担。换行不只是好看——是告诉读者"这里换了一个信息单元"。

## 修复
每段一个信息单元。检验标准：这段能用一句话概括吗？不能 → 该拆。

三段式信息密度节奏：
- 高密度事实（数据、日期、数字）→ 一句一段，三句封顶
- 中等密度论述（因果、对比、判断）→ 2-3 句一段
- 低密度过渡/总结 → 可稍长

## 预防
- 写完读一遍：连续两个"。"包含两个不同主题 → 拆
- 段落超过 4 行 → 检查是否混入了第二个信息单元
- 自问：读者扫读时，每段的第一句能当该段的摘要吗？
