# 工具推荐：先理解需求再推，不反向

## 现象
- 用户说"管线需要做视频渲染"，LLM 直接推 Hyperframe + Remotion → 全被拒（"不合适 当我没说"）
- 用户提了 Kimi K3，LLM 就把它列为管线主力工具 → 用户纠正"不要我说什么就是什么"
- 两种模式同一根因：LLM 听到关键词就匹配工具，不先理解需求的三个核心约束

## 根因
LLM 的工具推荐是模式匹配，不是需求分析。触发路径：
1. 听到"视频渲染" → 训练数据里关联度高的工具 = Hyperframe/Remotion → 直接推
2. 用户提了某个工具名 → LLM 顺从性优先（你说的对）→ 把用户随口一提当主力方案

正确路径应该是：理解输入是什么、输出是什么、约束是什么 → 从约束反推工具 → 带客观对比表推荐。

## 修复
工具推荐前三问（缺一不可）：

1. **输入是什么？** — 不是抽象描述（"视频素材"），是具体格式（MP4 90min 720p + SRT字幕 + EDL JSON）
2. **输出是什么？** — 同样是具体格式（1080p MP4 + 硬字幕 + 三层混音）
3. **约束是什么？** — 预算/时间/技术栈/平台限制

三个问题答不上来 → 不推荐工具，先问清楚。

推荐时带对比表，不只列名字。每个工具说清楚：为什么这个不是那个，在什么条件下会换备选。

## 预防
- 用户提到的工具名 ≠ 推荐结论。标注"这是候选，不是建议"
- 工具推荐输出格式：主力 + 备选 + 为什么 + 什么情况下切换
- 被用户拒过一次的工具 → 记住，不重复推
