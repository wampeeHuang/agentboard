# Agent 误读跨会话粘贴文本

## 现象
- 用户在 Claude Code 里粘贴了从其他对话复制的文本（"明天会直接在workspace新建一个生活向视频解说项目"）
- Agent 当成给本会话的指令，写入了 HANDOFF.md 的"明天会话环境"小节
- 用户纠正后才删除

## 根因
Agent 默认所有用户输入都是给当前会话的。无法区分三种情况：
1. 给本会话的指令
2. 用户自言自语/笔记
3. 从其他对话粘贴的错误文本

用户可能同时开多个会话窗口，粘贴错误无法通过 UI 层面预防。

## 修复
Agent 侧：当用户输入提到跟当前项目上下文**完全无关**的新项目名、新任务、新工作目录时，先确认再行动。

确认话术：`"刚才那段提到[新项目名]，是给本会话的指令还是贴错了？"`

不需要每次都问——只在"新话题跟当前项目完全无关"时触发。如果是在当前项目上下文的自然延伸（比如"顺便帮我也看看 XX 文件"），不触发此检查。

## 预防
这是 Agent 层面的判断规则，不是用户行为能解决的。用户无法保证永远不会贴错窗口。
