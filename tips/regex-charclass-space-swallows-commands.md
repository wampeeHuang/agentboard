# 正则字符类里混进空格 / 漏字母：解析器静默错到底

## 现象

写 SVG 路径分词器，用正则切「指令字母 + 数字」：

```python
re.findall(r"[MLHVAZmlhvacz]|-?\d*\.?\d+(?:e-?\d+)?", d)
```

同一段路径 `M673 -23C1029 -23 1237 156`，期望切出 `['M','673','-23','C','1029',...]`，
实际得到 `['M','673','-23','1029','-23','1237','156']`——**字母 `C` 消失了**。

后果不是报错，而是静默错值：所有三次贝塞尔段被当成直线，几何审计得出**完全相反的结论**
（把正确的「背对背」判成「画反了」），而且 9 个文件全报同一个错，看起来"很像真的"。

## 根因（两个叠在一起）

1. **字符类里混进了一个空格**：`[MLHVAZm lhvacz]`——肉眼几乎看不出来，但 `C`/`c` 不在类里。
2. **数字分支允许跳过字符**：`-?\d*\.?\d+` 在 `-23C1029` 上，会先匹配到 `-23`，
   然后从 `C` 之后的位置重新匹配出 `1029`——**正则引擎允许跳过不匹配的字符**，
   于是 `C` 被无声吞掉。

## 修复

```python
# ① 指令类只写大写 + (?i)，别再手工罗列大小写（漏一个就是静默错）
# ② 数字分支用 [-+]?(?:\d+\.?\d*|\.\d+)，必须有数字开头，不能跳过字符
re.findall(r"(?i)[MLHVAZC]|[-+]?(?:\d+\.?\d*|\.\d+)(?:[eE][-+]?\d+)?", d)
```

另外 **SVG 支持隐式重复指令**（`M0 0C...` 之后只跟数字、不重复写 `C`），
解析循环必须在"取完参数后下一个 token 仍是数字"时留在同一分支；同时要覆盖
`M/L/H/V/C/S/Q/T/A/Z` 全部指令——第一版只写了 `M/L/A/C`，遇到 `H` 直接抛异常。

## 预防

- **把正则源码打印出来用 `repr()` 看**，或用 `re.findall(r"\[([^\]]*)\]", pattern)` 把字符类抠出来逐字符核对。
  空格、全角字符、漏字母在这个位置完全不可见。
- **分词器必须有自检**，用已知答案的字符串断言输出序列（含「字母紧跟在负数后」这种边界，如 `-23C1029`）。
- 校验器对**全部输入报同一种错**时，先怀疑校验器，而不是被校验物。
- 与 `pycompile-quiet-swallows-error.md` 同族：那条是"参数让校验器静默失效"，
  这条是"正则让解析器静默错值"。共同点——**解析/校验的静默错值比报错危险得多**。
