# 字体轮廓转 SVG：量纲混用是这类活的主要 bug 源

## 现象

用 fontTools 取字形轮廓生成 SVG 字标，产出结果反复出错，且**每次错法都不一样**：

| 症状 | 真实原因 |
|---|---|
| 三个汉字几乎叠在一个点上 | 把「画布单位」的字形内偏移写进组内 `transform`，组上挂着 `scale(0.02)`，**偏移先与字体单位相加、再一起被缩了 50 倍** |
| 文字被顶出画布（差约 60 倍） | 排版时 X 用画布单位累加（`advance*scale`），Y 却留着字体单位（~1400） |
| 文字整体偏移一倍 | 字形归零与布局平移**各做了一次**，同方向叠加 |
| 组件宽度差 38 倍 | 归零时把画布单位的 pen 值当字体单位参与运算 |

## 根因

字体单位（upm 1000~2048）与画布单位（十几到几百）差 1~2 个数量级。
一旦某个中间量在两种单位间来回换算，**错误不会抛异常，只会画歪**。
而 SVG 的 `transform="translate(A) scale(s)"` 是**左乘**语义：
作用于点 p 得到 `A + s·p`——所以 A 是画布单位、p 是组内单位，混一次就错。

## 修复（可复用的排版契约）

**给每个函数规定"入参/出参只用一种单位"，写进 docstring，并让量纲在边界处一次性转换：**

```
字体单位层：outline() / 路径平移(归零)
边界一次：scale = size / upm
画布单位层：布局位置、组 transform、viewBox、墨迹包围盒
```

具体两条硬规则：

1. **在字体单位内把字形墨迹归零**（`_shift_path(d, -gx0, -gy0)`，|偏移| 小、精度高），
   然后**整个字形的偏移直接烘进路径坐标**（`_shift_path(d, off/scale, 0)`），
   不要写 `<path transform="translate(off)">`——那是踩坑点。
2. **组上的 `translate` 必须是画布单位、`scale` 内的坐标必须是组内单位**；
   任何时候想"把已经换算好的坐标塞进 scale 内层"都是错的。

## 预防

- **给生成器加内建断言**：算出的内容包围盒必须与 viewBox 一致（本项目的 `assert_sane`，
  9 个文件留边全部 2.00），不一致就中止、不产出坏文件。这比事后校验有用得多。
- **渲染验证要看位图，不能只看坐标数字**。本项目一度用 `getBoundingClientRect` 的数值
  "证明"布局正确，而截图里字符明显重叠——数值与视觉冲突时，先怀疑测量口径。
- **`getBBox()` 和 `getBoundingClientRect()` 都不含描边**（已实测：一条 `stroke-width=10` 的直线，
  两者宽度都报 0），不要以为其中一个含描边而重复外扩。
- 拿同一个"已知正确"的参照物做对照实验（例如同一个矩形分别用坐标与 transform 摆放，
  断言两者屏幕位置相同），可以快速判定"是渲染器不生效"还是"自己算错了"。
