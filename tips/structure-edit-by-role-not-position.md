# 改别人的结构文件：按角色分类，不要按位置猜

## 现象
给一张别人手工维护的 Obsidian 画布加一列，需要"按画布自己说明卡写的规则重算维度行颜色"。我用
**`x < 0` 且有子节点** 认维度行 —— 结果把 **根节点、`类别` 表头、矩阵表头、7 个类别分组**一起改了色
（它们都在左栏、都有子节点）。
改错后写"修正脚本"，又把**站点列头**认成 `kids[root]`（实际它们是 **`站点` 那一行的子节点**：
角色挂在"行"上，不在"根"上）→ 列头被当成"其余"**去了色**；同一脚本还按 y 序重排了站卡配色，
**动了用户原画布自己的配色**。

## 根因
坐标与"长什么样"是**布局的偶然结果**，不是**角色的声明**。结构文件（画布 / 配置 / 图 / 表）里
同一片区域必然混着多种角色：根、表头、分组、维度行、单元格、卡片，它们的 x/y 常常相近甚至相同
（实测：站点表头 `y=798`、站点列头 `y=800`，差 2px）。
按位置/形状选择，等于把"当前排版"当成"语义分类"，排版一改判据就错。

## 修复/步骤
1. **先取参照快照**：改之前把那一个文件复制成带时间戳的备份（`_runtime/canvas-backup/<名>.<stamp>`）。
2. **按角色枚举**，每条角色给出可判定的依据（不是坐标）：
   根 = 无入边 + 有出边 + 宽 < 400；说明卡 = 无入边 + 无出边；维度行 = **表头节点的子节点**；
   列头 = **"站点"行的子节点**；单元格 = 文本含"："；卡片 = 以 `**` 开头且含 `[[…canvas]]`。
3. **规则只作用于已确认角色的 id 集合**，其余一律不动。
4. 出错后用**参照快照逐节点还原**（按文本 → 颜色的映射回写），再只对目标角色应用规则。
5. **复验按同一套角色规则逐节点核对**（"仍未符合的行 = 0"）。

## 预防
- 改别人的文件前先问三句：**这份文件里有哪些角色？我要动的是哪一个？凭什么判定它是那个角色？**
- 判据里出现 `x`、`y`、`width`、`索引位置`、`第 N 个` 时，先怀疑：这是布局还是语义？
- "修错"时不要在同一套错判据上打补丁 —— 回到参照快照，换成角色判据重做一遍更快。
- 用户手工维护过的文件，**原配色/原排版本身就是用户的判据**，不属于本次任务就不要动。
