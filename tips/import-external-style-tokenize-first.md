# 抄外部参考样式：颜色先落目标系统的皮肤 token 层，不直接拷 hex

## 现象

从另一套设计系统抄代码窗样式到 supervisor 面板。参考源 vivi 说明书用 `--dark-panel: #3E571C` / `--dark-code: #223013` / `--dark-bar: #2F4519` 等色值。直接把 hex 写进目标 HTML 的 `<style>` 也能显示，但破坏「颜色只在皮肤 token 文件定义」的契约——换皮时这些颜色不跟随。

## 步骤

1. 读参考源 CSS，拆全视觉结构（背景层 / 面板层 / 内容层）+ 提取色板
2. 对照目标系统皮肤 token（如 default.css :root）——已有 token 直接复用。本案例深绿背景恰好等于已有 `--c-accent`，不新建重复值
3. 缺的颜色补成新 token，集中定义；结构层（HTML/CSS）只用 `var(--token)` 引用，零 hex
4. 跑目标系统门禁验证（如 `check-skin.js`）

## 为什么

- 皮肤单一真相源：颜色只在一个文件，换皮改一处全站跟随
- 抄来的色值带「参考系统的血缘」，token 化后才成为目标系统的资产
- 跨系统抄样式迟早发生，步骤固定，值得固化

## 预防

- 抄参考样式第一步永远是「列色板 → 对 token」，不是直接贴样式
- 参考色的视觉角色（背景深绿、标题栏、面板体）映射到目标 token 语义，不按色值原样搬名
- 配套参考 `reskin-audit-by-value-not-name.md`（换皮后按值审计）
