# OCR 双向字形混淆：修复规则必须逐例备份验证，"看似错"可能本来就是对的

## 现象
文本 OCR 损坏出现 干↔于 双向混淆（干 错成 于：干脆→于脆、干净→于净；于 错成 干：关于→关干、快于预期→快干预期）。写修复规则时，`于完→干完` 规则**纯破坏**——备份验证原始全部 14 处 `于完` 都合法（等于完美/至于完全/趋于完整/终于完全/不至于完全…），`干完` 原始 0 处。规则一次改坏 13 个词，v4 的反向规则（于→干）碰巧把它们全部还原。

## 根因
OCR 混淆是**双向**的，且正确方向占多数。想当然"于 后面接 完 必是 干完"是错的前提——`于完` 在"至于/等于/趋于/终于"这些组合里大量合法存在。批量替换规则对高频合法串下手，错杀远大于修复。

## 修复
1. **逐例备份验证**：每条替换规则应用前，从 backup 版本统计 `旧串` 和 `新串` 各自的出现次数与上下文，逐例判断方向。
2. **频次反证**：若 `新串`（目标正确串）在备份里出现 0 次、而 `旧串`（待替换串）大量存在——说明旧串本来就是合法的，规则方向错了。
3. **短词锚定上下文**：两字混淆词（干/于）不能裸替换，必须按完整词语或正则负向断言锚定（如 `(?<!至)于嘛→干嘛`、`(?<!趋)于活→干活`），避免误伤合法组合。
4. **canonical 脚本幂等**：修复脚本可重复跑，`dry` 模式验证幂等（无命中 = 已收敛）。已证破坏的规则立即从 canonical 移除，不留历史版本。

## 预防
- 任何 OCR/转写修复任务的替换规则，先跑 backup 对比统计，再决定方向和锚定。
- "看着像 OCR 错的串"先假设合法，证据（频次/上下文）证明是错才替换。
- 保留备份 + 幂等脚本 + 可回溯，修复可回滚。

## 适用
干↔于、己↔已、味↔昧、步↔生、望↔蒋 等 OCR 字形混淆，以及拼音残留（sè/ri/xing）批量修复。灵剑山修复主脚本：`D:\Obsidian\_runtime\fix_corrupt.py`（v5，幂等），备份在 `_runtime/backup/`。
