# 验证标准写原则不写硬编码数字

## 现象

quality-tiers.md 写了"16 个必填 token"作为精选标准。code review 追问下发现：16 是 validate.mjs 硬编码的当前模板公约数快照。Swiss 体系模板用 `--paper`/`--ink` 命名，按硬编码名单检查全 FAIL——但它们的 token 引用是闭合的，质量没问题。

## 根因

把验证脚本的实现细节（当前快照的公约数）当成了质量原则写出去了。标准文档是给人读的合约，实现是给机器跑的代码——两者不能混。

## 修复

标准文档写原则：**"HTML 中所有 `var(--*)` 引用的变量在 tokens.json 中有定义（引用闭合）。"** 实现可以换——从硬编码 16 个名单换成差集扫描脚本——原则不变。数字是快照，原则是真理。

## 预防

标准文档出现数字时追问：这个数字是"当前恰好如此"，还是"永远应该如此"？前者 → 改为原则陈述，数字可以出现在实现代码里。后者 → 保留。
