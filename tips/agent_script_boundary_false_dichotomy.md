# 管线 Agent/脚本 边界画线陷阱

type: methodology
date: 2026-07-21
source: 音乐作坊方法论修正 v1→v2

## 现象
方法论中画了死线"AI 只判断不执行 / 脚本只执行不判断 / AI 不操作文件系统 / AI 不调 API"——导致文档描述与管线 Agent 实际能力矛盾。用户纠正后推翻重写（20处修改）。

## 根因
混淆了两个概念：
- "不应让 Agent 每次重复思考机械步骤" ≠ "Agent 不能做"
- Agent 能调 API、写文件、操作飞书（通过工具）——机械步骤应脚本化的原因是零判断、可固化，不是 Agent 技术上做不到

## 修复
边界区分标准改为：**需不需要语义判断**
- 需要语义判断（风格翻译/歌词/LRC清洗/封面文案）→ AI 创意节点，Agent 自己做
- 不需语义判断（ffmpeg/whisper/文件操作/API转发/HTML渲染）→ 脚本化，Agent 调脚本执行
- 不要在文档中写"AI 不操作文件系统"——Agent 通过工具就在操作文件系统

## 预防
定义 Agent/脚本 边界前，先跑一遍实际管线看 Agent 实际做了什么。设计文档描述现实，不制造假边界。
