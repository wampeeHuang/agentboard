# Agent 写中文技术文章——修不完的迭代循环

## 现象

每次用户指出一个问题 → 只修那个点 → 交差 → 用户发现下一类问题 → 再修 → 循环。没有一次性把同类问题全局扫描完。

具体案例（同一篇文章）：
1. "扁平模块不需要 AGENTS.md？"→ 加了 AGENTS.md
2. "目录树是编造的"→ 去调研真实仓库
3. "为什么只介绍流水线"→ 补全六个范式
4. "案例太特殊有噪音"→ 换成共性提取
5. "标题没序号"→ 加序号
6. "来源只有 1 个"→ 补到 3+
7. "目录树注释不全"→ 补齐注释
……每轮都是"修这个症状"，不是"还有什么同类问题"

## 根因

三层问题叠在一起：

1. **没有检查清单。** 用户信任 `check.js`/`inspection.json` 门禁模式（程序验证 > 人眼），但写文章时没建等效的验证脚本。改完就跑，不跑全局一致性检查。

2. **搜完才写 vs 写了再修。** 第一版目录树是凭记忆编造的。宪法写了"独立调研先于方案确认"，但在"写文章"这种任务没照做。

3. **只修一个点，不扫同类。** 用户指出序号 → 加序号（不管来源、注释、案例）。被纠正一次想一次，不主动问"这个类别下还有什么同类问题"。

## 修复

当次修复：逐条对齐。后续文章按预防清单走。

## 预防

写/改技术文章前，先做三件事再动笔：

1. **读关联笔记 → 提取为检查清单。** 涉及的原理笔记（如金字塔原理）逐条转成可检查的布尔项。不依赖"我记得"。

2. **外部调研先完成。** 每个范式 ≥3 个来源交叉验证。搜够再写，不是写完被说"案例不对"才去搜。

3. **全局模板先定好，逐个套。** 别逐个范式写——先定模板（树格式、注释规范、来源格式），六个范式一起套，确保一致性。写完全量跑检查清单。
