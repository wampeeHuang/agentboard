# 知识库 vs 项目方案 边界混淆

type: principle
date: 2026-08-07
source: 治愈系解说管线知识库构建 — 管线设计/闸门/混音参数多次被误写入 Obsidian 知识库

## 现象
- LLM 产出结构化内容（管线阶段表、自动化分级、混音参数）后，默认当"知识"写入知识库
- 看起来像知识：有表格、有对比、有层级
- 实际是推演/设计方案：没有外部来源可验证，绑定具体项目上下文
- 用户反复要求删除后，才意识到不是"内容不够好"，是"性质判断一开始就错了"

## 根因
LLM 无法区分两类内容：
- **知识**：可被外部来源验证，脱离项目上下文仍成立（例：Mosfilm YouTube 频道有数百部免费电影）
- **项目方案**：推演/设计/假设，绑定具体项目（例：管线分 8 阶段，G2 是最关键闸门）

LLM 在生成结构化内容时获得的确定性错觉——格式越整齐，越觉得自己说的是事实。格式工整 ≠ 内容可验证。

## 修复
落盘前单向判断：

**这个内容能发出去给别人当参考资料吗？**

- 能 → 知识库。每条关键断言须有外部 URL 或公认事实支撑
- 不能 → 项目方案。放项目目录，标注"设计草案，待实践验证"

判断不是模糊的"感觉像知识"——是硬检查：给一个没见过这个项目的人看这一页，他能分辨哪些是事实哪些是设计吗？

## 预防
- 写 Obsidian/知识库页面后在末尾加一行：`<!-- verified_sources: [URL1, URL2] 或 [none - project plan] -->`
- 没有 URL 的出现在 markdown 文件中 → 要么是项目方案（搬走），要么是未验证推测（找来源或删除）
- 知识库 CI：grep 知识库目录，标记所有"应该进项目目录"的页面类型（管线设计、参数表、阶段定义、创作者公式）
