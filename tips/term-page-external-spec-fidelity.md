# 术语页索引外部规范先验证术语真在规范里；本地约定不术语化（删，不标注）

## 现象

wiki 术语页「四槽位」要把本地命名 `_runtime/` 写进去。第一版我加了一节「来源归属要分清」，把 `_runtime/` 标成「本地扩展槽」保留。用户纠正：「我不要本地约定，我要规范，我要外部对齐。」方向错了——要的是删，不是标注。

## 根因

- `_runtime/` 是 supervisor 本地命名，agentskills.io 开放规范里只有 SKILL.md/scripts/references/assets，没有它
- 术语层的作用是索引「可被外部验证的规范」；本地约定一旦术语化，读者无法判断它是规范还是私有，且各项目名各叫各的（MLflow `mlruns/`、koru `.planfile/`、pitboss `.pitboss/`）
- 「标注本地扩展」看似谨慎，实际是把本地约定塞进规范层，方向就错了

## 修复/步骤

1. 术语页若声称索引某外部规范，先到规范原文（WebFetch 官方文档）验证每个术语真实存在
2. 验证不在规范内 → 确认是本地约定，从术语页删除，不标注保留
3. 本地约定留在项目自身文档（如 AGENTS.md），或进「本地约定」专属位置，不混进规范术语层
4. 行业名不统一的名词，用「事实表 + 多实例」呈现（各项目叫什么），不造伪规范

## 预防

- 写规范类术语页前先问：这个术语在外部可索引来源里存在吗？不存在 = 不术语化
- 用户说「要规范、要外部对齐」时，删除本地扩展槽，不是给它贴标签
- 配套参考 `concept-page-implementation-leak.md`（概念页不泄漏本 vault 实现细节）——本 tip 是「外部规范保真度」方向，那条是「实现不侵入概念」方向
