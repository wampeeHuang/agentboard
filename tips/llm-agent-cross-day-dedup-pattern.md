# LLM Agent 跨日查重模式：7天窗口 + URL精确 + 标题模糊

type: pattern
date: 2026-07-30
source: evopearl-data v2 — 三个日报栏目均缺查重，频繁推送重复内容

## 问题

LLM agent 每天独立运行，不知道之前产出过什么。重复内容被多次推送，用户信任度下降。

## 方案

在 agent prompt 中增加查重 Gate（Gate 0.5），评分前执行：

1. **读历史**: 加载同栏目 `data/{task}/` 最近7天 `YYYY-MM-DD.json`
2. **提取去重集**: 从每个文件的 `selected[]` 提取 `url` + `title`
3. **双重匹配**:
   - URL 完全匹配 → 直接过滤
   - 标题相似度 >80%（关键词重叠判断） → 标注疑似重复，过滤
4. **强制日志**: 输出 `dedupLog` 字符串和 `meta.dedupFiltered` 数字

Prompt 模板（可复用）:
```markdown
### 跨日查重（评分前必做）

1. 读取 `data/{DATA_TYPE}/` 最近7天的 JSON 文件
2. 提取所有已入选条目的 url 和 title
3. URL完全匹配 → 过滤；标题相似度>80% → 过滤
4. 输出: 「跨日查重完成: 总候选 X 条, 重复已过滤 Y 条, 保留 Z 条进入评分」

查重失败的日期文件 → 跳过，标注"该日数据不可用"，不阻塞流程
```

## 适用场景

- 任何 LLM agent 定期产出内容且需要去重的场景
- 不依赖外部数据库（如飞书/MySQL），agent 直接读自己的历史文件
- 适合日均条目 <50 的小规模策展场景

## 局限性

- 标题相似度判断依赖 agent 的语义理解，不够精确
- 同一内容被不同源报道（不同URL+不同标题）可能漏网
- 7天窗口外重复无法检测
- 不适用于大规模去重（>1000条/天），此时应上 embedding 或 simhash
