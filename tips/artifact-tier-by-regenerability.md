# 产物分层看"能不能再造"，不看"是不是我生成的"：双层排除目录是证据坟场

## 现象
工作区治理时把审查子代理产出的 9 个审计产物（4 个 JSON + 5 张截图）从 `_knowledge_base/` 移进 `_runtime/audit-20260905/`。
移动后核对才发现：`_runtime/` 同时被 **两套保护机制排除**——`.gitignore` 排除（不入版本控制）+ robocopy `/XD` 排除（不进异地镜像）。
那 5 张截图是子代理现场截图，**不可能再生成**，却瞬间从"有一层备份"变成"零备份"。
更隐蔽的是那 4 个 JSON：它们原本被 git 跟踪，`git mv` 到被忽略的目录后 **git 不会自动解除跟踪**——索引里仍留着它们，
于是出现 `_runtime/` 里躺着一批"名义上不入 git、实际上被 git 跟踪"的文件，与文档声明直接矛盾。

## 根因
分层判据用错了维度。当时用的是**"谁生成的"**：子代理/自己跑出来的 → 归运行态。
正确判据是**"删了还能不能再造"**：
- 可再造（缩略图缓存、op-log、可重跑的验证产物）→ 运行态，随便丢
- 不可再造（审计快照、现场截图、旧稿）→ 归档层，必须进版本控制 + 进备份

用"谁生成的"分层，会把一次性证据当垃圾扔进最不设防的目录；而双层排除目录恰好是防护最弱的地方。
另外 `git mv` 进被忽略目录还有个连带坑：之后再执行 `git add -A -- <原目录>` 会报
`fatal: pathspec did not match any files`（原路径已不在索引、新路径被忽略），需要
`git rm -r --cached <目标>` 再 `git add <新位置>` 才能把索引改对。

## 修复/步骤
1. 把 9 个不可再生产物整体移到 `archive/2026-09/audit-20260905/`（归档层：入 git + 进 robocopy）
2. `git rm -r --cached --ignore-unmatch "_runtime/audit-20260905"` 清掉残留索引项
3. `git add -A -- archive/2026-09/audit-20260905`（git 自动识别为 rename，历史不断）
4. 把 `archive` 从 robocopy 的 `/XD` 排除列表里删掉——归档既然"有保留语义"，就必须被镜像
5. 在项目 CLAUDE.md 写死判据："`_runtime` 只放删了能重建的东西；不可再生的证据一律进 `archive`"

## 预防
- 新建 `_runtime` / `.cache` / `tmp` 一类目录时，先问：**这个目录有几层保护？** 同时被 git 和备份排除的目录，只允许放可再造物
- 分层判据固定为"可再造性"，不要用"生成者 / 是否自动产出 / 是否临时"
- `git mv` 进被 `.gitignore` 覆盖的目录后，立刻 `git status` 确认是 `R` 而不是 `RD`；跟踪状态不会因落点被忽略而自动解除
- 备份排除列表里每加一项，都要能回答"这一项里有没有不可再造的东西"；`archive` 这类**有保留语义**的目录不进排除列表
