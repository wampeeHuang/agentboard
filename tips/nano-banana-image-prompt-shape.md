# Nano Banana / Gemini 系图像模型：提示词该写成什么形态

## 现象

同一段需求，用"规格书式"提示词（8 个【】小节 + 一长串【禁止】）反复出图，质量一直不理想：
画面有 AI 味、构图堆砌无层次、出现不该有的外框、背景某块"没被定义"成一片白。
用户直接问："你的提示词会不会太多了？多好还是少好？"

## 根因

**这类模型是 LLM 驱动的（Gemini 基座），不是 SDXL 那种扩散模型，所以提示词行为完全不同。**
社区提示词指南的核心几条（原文要点）：

1. **给连贯的句子，不要关键词串。**
2. **说清这张图是"为什么"，不只说里面有什么；一段叙述，然后靠多轮对话去修。** —— 不是一次写全规格书。
3. **约束尽量写成你"想要"什么，而不是一串禁令**——模型对正面描述更可靠。
   （「不出现第二个人」→「画面里只有她一个人」；「不要文字水印」→ 干脆不写，不写更不容易想到。）
4. **风格标签太宽泛会平均成素材库插画。** 要描述**做法**：线的粗细、平涂还是晕染、配色行为、
   标志性质感。点名画室/节目/画家也没用，要描述观感本身。
5. **要保持人物一致就完整描述人物**；漂了要**回到完整描述重开**，不要在漂掉的结果上继续指。
6. **往插画方向推的任务，指令要短**——堆约束反而有害。
7. **相机/照片词汇会把风格化的图拉回照片**（「轻微反光」「质感」这类词要删）。

**另一条独立于模型、纯构图的坑**：**留白 ≠ 未定义。**
为了修「图片周围有框」，很容易写下"画面内容一直画到图像最外沿"——那是拿技术补丁杀掉留白，
画面全实、死板。而反过来说"留白"或"干净素色"，模型会照字面留一片白，用户看到的是
"背景有一部分没有被定义"。

## 修复/步骤

**主提示词的结构（一段叙述，不是规格书）：**

```
把第一张参考图里那位<主体>画进下面这个场景。

画法：<写做法，不是标签>—— 匀细的墨线勾边，色块平涂不晕染，<主色>打底，金色只点在<哪里>，
整体明亮通透，像一张印在纸上的老广告画。竖构图 9:16。

构图要虚实相生：
<主体>是最实的一处——最亮、最清楚、墨线最利；
<次要元素>中央最密，向两侧、向上越远越虚：线越少、色越淡、边缘越柔，最后融进暖光里。
<主体>四周那片空，是**被暖光填满的虚，有色、有温度、有空气感，不是白色的空**。
画面四边都以虚收口——边缘的花与光自然地淡出去，不要出现一条死白的边。

<场景与主体描述，分几段自然语言>

<灯光一段：谁最亮、轮廓光从哪来、明度分几层>

<一致性要求一段：完整描述而不只是"照参考图">

<约束用正面句：画面里只有她一个人、一支麦克风>
```

**三个可操作判据：**

| 判据 | 做法 |
|---|---|
| 画法要放最前面 | 它决定质感；放在末尾会被前面的约束淹没 |
| 约束翻成正面句 | 逐条检查：这一句是"不要 X"吗？能不能改写成"只有 Y"？ |
| 留白必须被定义 | 凡希望"空"的地方，写成"那里有什么"（被光照亮的幕布/暖光/空气），不要写"不放什么" |

**改不动的兜底**：把**风格样本作为参考图传进去**（"第一张是人物，第二张只用它的画法"），
比用文字描述画法可靠得多。

**"多好还是少好"的答案是结构问题不是长度问题**：第一轮一段叙述把该说的说完，
其余调整**每轮只发一条短指令**（"让画面整体再亮一些、更通透""拱顶那团花再大再密，向两侧再稀疏一些"）。
一次发十条等于回到规格书。
