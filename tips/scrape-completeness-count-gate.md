# 抓取完整性判据：源页面的条目数 == 收录数，差必须为 0

## 现象（同一轮里发生了两次，都一路绿灯）

**事故一 · 整页静默丢数据。** WikiArt 有 9 本并列的「词典」页。其中
`media / century / nation / school / field` 五页**没有 `li.header`**（它们本身就是扁平列表）。
解析器写成「**先有组才收项**」（`for li: if header: 开组; elif dottedItem and cur: 收项`），
于是这五页的词条**一个都没收**，报告 `0 项`。

**事故二 · 只抓了一部分还自认完整。** 同一个站其实有 9 本词典，
只列了 2 本（流派 / 题材），漏掉 7 本 —— 里面正有用户最想要的「艺术运动」(189)
和「画派与团体」(289)。**漏了 1039 项，没有任何东西拦它。**

## 根因

**没有一条判据在问「源页面上到底有多少条」。** 解析成功、JSON 合法、流程走完 —— 全绿。

## 口径：三条判据，不靠 Agent 自证

| 判据 | 抓什么 | 怎么判 |
| --- | --- | --- |
| **一 · 完整性** | **漏** | **源页面的条目标记数 == 收录条数，差必须为 0** |
| **二 · 结构保真** | **发明** | 产出上的**每一层**都要能在源页面找到对应标记；指认不出 = 自创 |
| **三 · 可复算** | **不可重现** | **现在重新抓一遍、重新解析、逐项 diff**，差必须为 0 |

判据三要**现场重抓**，不是重跑本地缓存 —— 缓存重跑只能证明"代码没变"，证明不了"数据没变"。

## 两条必须遵守的前提（否则判据是装饰）

1. **期望值必须来自外部事实**：源页面上的标记计数、**独立第二次抓取**的结果、或用户给的原始数据。
   **绝不能由"生成侧那套逻辑"算出来** —— 同源判据永远通过
   （项目里已有同款事故：`_process/lessons/20260916-把样本里的特例当通则…`，
   664 条箭头方向错了而闸门仍报 11/11）。
2. **翻译/映射那一步要单独抽检**，别混进上面三条。
   中文译名对不对，计数判据查不到；随机抽 20 条给人看，就能估错误率
   （超过约 5% 就该整表返工，不是逐条修）。

## 实现要点

- **项与组分开收集**，分组标记当**可选**：
  `if header: 开新组` / `else: 收项（没有组就收在一个无组名的组里）`。
  **不要把「有分组标记」当成收项的前置条件。**
- 判据脚本**只做比对**，源站适配器由调用方写 —— 每个站的标记口径都不同，
  硬抽一个通用适配器只会做出「看起来能拦、其实拦不住」的东西。
