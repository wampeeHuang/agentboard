# 概念页被解耦工作改写成实现文档

## 现象
概念页出现本 vault 的具体文件名（check.js、SCHEMA.md）、行数（~70 行）、"当前选择：单次编译 + 嵌入式"等 vault 特有决策。页面零外部信源，不满足概念升级门禁。

## 根因
大规模规范化工作（如模板-SCHEMA 解耦）会产生大量"这个规则怎么落地"的即时决策。这些决策被就近写入了当时正在编辑的概念页，而不是单独建立实现文档。解耦本应分离关注点，却造成了实现细节向概念层的泄漏。

## 修复
1. 提取 vault 实现细节 → `references/` 目录新建实现文档
2. 概念页重写为抽象描述（"入口文件"不是"CLAUDE.md"，"验证脚本"不是"check.js"）
3. 补外部信源验证通用性（≥3 信源）
4. 概念页延伸阅读指向实现文档

## 预防
概念页写完自检：不出现本 vault 具体文件名。出现 = 实现侵入。
判断标准：把这页发给另一个 Obsidian vault 的用户，他们能直接用吗？用不了 = 实现耦合。
