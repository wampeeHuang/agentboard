# 内部工具看板写成开发文档——受众错位

## 现象

给非工程师做的管线看板，信息架构按"怎么加新功能"组织——目录树列出的是文件路径、决策树写的是"新建 gate-xxx.py → 实现 check() 接口"。用户一眼指出"这是技术导向，不是设计架构导向"。

## 根因

Agent 默认用开发者视角组织信息。看到代码仓库有 gate 脚本、flesh 规则、pipeline-state.py，自然写出"怎么扩展"的教学。但用户的真实需求是"出问题时怎么调"——他不知道也不需要知道新建 .py 的步骤。

核心判断：**操作路径 ≠ 实现路径。** 运营者需要 symptoms → diagnosis → action，开发者需要 file → interface → registration。两套完全不同的信息架构。

## 修复

1. 识别受众：看板给谁看？运营者还是开发者？如果是运营者，禁止出现 .py 文件名、函数签名、import 语句
2. 重构信息架构：从"想加什么功能 → 改哪些文件"翻转为"遇到什么问题 → 调哪个配置层"
3. 每条操作以"不改代码"结尾——这是运营者最关心的信息

## 预防：内部工具看板受众检查清单

每新增一个板块，过三条：
- 这个板块有大段代码或文件路径吗？→ 有 = 写偏了
- 用户看完知道"出问题时点哪里"吗？→ 不知道 = 缺操作路径
- 这个板块的概念从目录树/架构图的哪部分导出？→ 说不清 = 概念飘在空中
