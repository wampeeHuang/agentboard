# 论证"没人用"时，搜索范围必须含"被链接的下一层"

## 现象
要判断 `docs/` 目录该不该继续由本地服务提供，我给出的论据之一是「应用界面**零处**链 docs/」——
去 `index.html`、`library-ui.js`、`metadata-ui.js` 三个前端文件里 grep `docs/`，确实一处都没有。
用户追问一句「你说的是说明书吧，说明书 HTML 会在前端呈现呀」，复核后发现：

- `index.html:44` 有「说明书」按钮，`href="/README.html" target="_blank"`；
- `README.html:352 / :372` 两个 iframe 的 src 正是 `docs/diagrams/architecture.html`
  与 `docs/diagrams/retrieval.html`。

**真正的链条是：前端按钮 → README.html → 两张交互图 → `docs/`。**
我的搜索范围恰好把这条链的中间一环（前端唯一会打开的那一页）排除在外，
于是得出了一个听起来干净、实际把唯一反例漏掉的结论。删掉 `docs/`
会直接把说明书的两张图打成空白——那不是"没人用"，是产品呈现链的一环。

## 根因
选搜索范围时用的是"我手上方便的文件"，而不是"这个论断可能被谁推翻"。
「零处引用」这种全称否命题，要求搜索范围**覆盖全部可能的消费者**；只要范围里少一个，
结论就从"没人用"退化成"我没找到"。链路是分层的：直接链接（`index.html`）之外还有
**间接消费者**（被链接的页面再引用的资源），而后者天然不在"第一层文件"里。

## 修复/步骤
1. 复核时按"链路"逐层搜，而不是按"我打开过的文件"搜：
   `index.html` 的出链 → 每个被链页面的入链/iframe/fetch → 直到没有新页面。
2. 判定"某资源没人用"至少过三问：谁**直接**引用？谁**间接**引用（被链接页面的资源）？
   构建/发布脚本会不会引用（这类引用不在 HTML 里）？本项目里第三问的答案是"会"——
   `build-manual-site.py` 与 `subset_fonts.py` 都按文件名列出过这两个图。
3. 结论落地时把范围写进结论本身：「在 X、Y、Z 之内零引用」，而不是无范围的"零处引用"。

## 预防
- **全称否命题（"没人用/从来没/一处都没有"）先写清范围，再下结论。** 范围没写清的否定判断，
  默认当作未验证。
- 找"谁在用"时按**引用链**走，不走"文件夹清单"。被链接的下一层是最容易漏的反例所在。
- 同一会话里同类的"作用域错误"出现第二次，就该停下来检查自己的搜索口径而不是继续下结论：
  本次三个连错——作用域太大（按文件名数进程，把兄弟项目算进来）、太小（只查散落截图就说根目录干净）、
  恰好自证（只搜三个文件就断言零引用）。
- 让别人能反驳：把 grep 命令与文件清单一起给出。只给结论的"零处引用"，别人无法发现你漏了哪一层。
