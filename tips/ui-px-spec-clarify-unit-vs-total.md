# 视觉 px 规格「Xpx × N」先对齐指每块还是整行，再动手

## 现象
- 用户：筛选面板「保持 128px 乘以 3 的宽度」
- 我第 1 轮按「每块 128px」实现（整行 384px），还自作主张删了卡间距
- 用户：宽度不是 128×3 → 我改成 gap 0、整行精确 384px
- 第 3 轮用户亮出完整规格：**每块 384px、卡间距 16px、整行 3×384+2×16=1184px**
- 两轮全错，浪费两轮往返

## 根因
`Xpx × N` 里的 X 有歧义：指「每一块的宽」还是「总量（N 块的并排总宽）」？我听成前者，实际是后者语境里的单元宽。CSS 网格 1fr 拉伸让块宽随列数变——砍掉一维列数变少块就变宽，用户要的是把块宽钉回设计值（原四格时代单块 ~384），不是让整行变窄。

## 修复/步骤（行为规则）
视觉 px 规格动手前，先把三个数字对齐：

1. **X 指每块还是总量** —— 选项化提问带数字确认，别自己定稿
2. **间距多少** —— 卡间 gap，默认 16 也要问，别自作主张改成 0
3. **总量 = 每块 × N + 间距 × (N-1)** —— 心算验证给用户看

用户说「先自查现在出现了什么问题」时，先量现状逐项对照（getBoundingClientRect），再改。

## 预防
- 尺寸指令歧义 ≥3 会话踩过（灵感墙卡片列数、字荐尺寸指令）——**先量化对齐再实现是硬规则**
- 改 UI 前浏览器实测现值（块宽/行宽/间距数字输出），别只读 CSS
- 自作主张删间距 = 动设计默认值，先问
