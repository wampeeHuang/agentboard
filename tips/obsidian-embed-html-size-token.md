# Obsidian 内嵌 HTML 的尺寸写在 `![[文件|这一段]]` 里（embed-html 插件）

## 现象

把 4 个自包含架构图（HTML）用 `![[descript-架构图/xxx.html]]` 内嵌进 Obsidian 笔记后，用户反馈「视口高度太小，现在看不全，你至少做到 16:9」。

先怀疑是图太高，去改图；改不动才发现真正原因是**没给内嵌指定尺寸**，插件用了自己的默认值。

## 根因

`embed-html` 插件（mnaoumov，v2.5.x）把内嵌链接的 **`|` 后面那段文字当尺寸声明**：它从容器元素的 `alt` 属性取值（Obsidian 会把 `[[文件|这里]]` 的「这里」写进 `alt`），再交给内部的 `parseSizeSpec` 解析。

优先级是 **内嵌 token > 容器属性 > 插件设置**（`defaultWidth` / `defaultHeight`，可进设置界面改）。不写 token 就走插件默认值 —— 那通常偏小。

## 修复/步骤

三种写法都支持：

```markdown
![[图.html|1200x1000]]              <!-- 短式：宽x高 -->
![[图.html|width:1600;height:900]]   <!-- 声明式：可带 max-width/min-height/max-height -->
![[图.html|-]]                       <!-- 高度自适应内容 -->
```

写完后**在阅读视图查看**（编辑视图不渲染嵌入）。

## 预防

- 内嵌 HTML / PDF 这类"有自己页面尺寸"的资产，**一律显式给尺寸**，不要依赖插件默认值。
- 尺寸是**用户可自行调整**的：在设计交付里直接告诉用户「`|` 后面那个数字就是尺寸，想更宽改它」，比反复来回问「够不够大」高效。
- 想确认插件读的是哪个字段，不必猜：在这类社区插件的 `main.js` 里搜 `parseSizeSpec` / `defaultWidth` / `getSizeToken` 就能看到完整链路（体积大但可读，CSS 与业务逻辑混在一起）。
- 注意「用户说视口小」可能指两件事：**外框太小**（改 token 即可）或**图本身太高**（要改图）。先量图的实际宽高比再决定，别默认是后者。
