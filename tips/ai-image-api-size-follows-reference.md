# 图像 API 的尺寸：预设档会跟随参考图比例，要出固定画幅必须写显式宽高

## 现象

给"图生图 / 多图参考"的请求里写 `"size": "2K"`（预设档），
期望出 9:16 竖屏，实际出来的是**横版**——与参考图（一张 16:9 的三视图）同比例。

## 根因

多数图像 API 的 `size` 参数有**两种语义**：

- **预设档**（`1K` / `2K` / `4K`）＝ 像素量级，**比例跟随输入参考图**
- **显式宽高**（`1440x2560`）＝ 同时锁定比例

传了参考图又用预设档，比例就被参考图接管了。

## 修复/步骤

1. **要固定画幅就必须写显式宽高**，不要用预设档。
   例：`"size": "1440x2560"`（＝ 9:16）。
2. **核对该平台的尺寸约束**。以火山方舟 Seedream 为例（插件文档给出的约束）：
   - 宽高必须是 **16 的倍数**
   - 比例在 **1:16 ~ 16:1** 之间
   - 总像素在 **921600 ~ 4194304** 之间
   `1440×2560 = 3,686,400` 像素，宽高都是 16 的倍数，比例 0.5625 = 9:16 ✅ 全部合规。
3. **网页端同理**：上传横版参考图时，一定要在界面里**手动选竖屏比例**，不要让它"跟随参考图"。
4. **写完先干跑打印请求体**再真调（本次的坑就是在干跑里看到的）。
   干跑只打印、不发请求，成本为零，能挡掉"白跑一次"和"白花一次额度"。

## 相关

- 请求格式与字段名以平台文档为准；OpenAI 兼容接口的图像生成走
  `POST {base_url}/images/generations`，参考图放 `image` 字段（数组即为多图融合）。
- 同类"参数默认值悄悄改变语义"的坑：`denoise`（图生图唯一命门参数，按重绘幅度选：
  0.25–0.35 只改细节 / 0.40–0.55 换表情姿态 / 0.60–0.75 大改构图且一致性开始崩）。
