# 抓取小说重复不是随机，作者请假/延迟通知标记会触发抓取器重抓同一页

## 现象
灵剑山（从前有座灵剑山.md）有 11 个"整章重复块"，每块前面都有作者通知行（`更新延迟一下` / `请个假` / `小请个假` / `通知,更新延迟一下`）。共 1505 行冗余。初看像随机重复段落，实际是**整章被重抓**。

## 根因
这些标记行是作者的"本章更新时间通知"。抓取器把含这些标记的页当作"新内容页"再次抓取 → 同一章被原样抓两遍，以标记行为界整块重复。

## 修复
1. **找重复块**：按行哈希分组，对每组做最大连续匹配（两位置同时向后逐行相等），取最长 k ≥ 4 行。用区间重叠聚类合并成簇（源区间相邻/重叠 + 副本区间相邻/重叠 归并），避免逐行 offset 各自成链的碎片化。
2. **定规则**：保留首次出现，删后续逐字重复副本。前提是逐字匹配——语义近似不删。
3. **安全删除**：删除脚本带边界断言——每个区间校验起始行/结尾行应含内容（容忍起始空行、结尾空行），任一不匹配立即中止；区间互不重叠检查；自下而上删；先备份。
4. **拼接点人工验证**：删完逐点读上下文，确认内容→标题或内容→空行→标题风格与文件一致。

# dedupe_find.py 核心：最大连续行匹配

## 预防
- 抓取器对含"作者通知/更新时间标记"的页做重抓判定前，先查该页是否已抓过（URL 或章节标题去重）。
- 清理此类文件，先跑重复块检测看边界标记，别按"重复段落"猜——标记行是去重的天然锚点。

## 适用
任何分章抓取的小说/长文，作者在正文里嵌通知行、抓取器按内容判新的场景。灵剑山去重脚本：`D:\Obsidian\_runtime\dedupe_find.py` / `dedupe_apply.py`（gitignored）。
