# 安装器/写外部目录脚本的沙盒测试法

## 能力

验证一个"写受保护外部目录"的脚本（安装器、provisioner、部署脚本）在真实环境外跑通成功/失败两条路径，真实文件零污染。

## 为什么只能用这个

直接跑会碰真实目标（如 Program Files 的 OBS），改坏用户环境不可逆。纯 dry-run 往往不覆盖"真的写文件 + 真读环境变量 + 真杀进程"的完整逻辑。沙盒隔离是唯一能全路径实测又零污染的方式。

## 步骤

1. **镜像完整目录**：把脚本 + 它依赖的旁支目录（如 `plugin/`、`panel/`）整份 copy 到隔离目录，脚本相对路径照常解析
2. **伪造目标目录**：按脚本探测逻辑造出假目标（如 `bin/64bit/obs64.exe`、`obs-plugins/64bit`），脚本能找到它、写进去
3. **隔离环境变量**：脚本读的环境变量（如 `%APPDATA%`）重定向到假目录，`set "APPDATA=%~dp0fakeappdata"`，别污染真环境
4. **打补丁防误伤真实进程**：脚本里 `tasklist`/`taskkill` 的进程名改成假名（如 `obs64.exe`→`obs64-fake-test.exe`），测"检测到运行中"分支时不会杀真进程
5. **跑成功路径**：断言 EXIT=0 + 产物全部落盘（数量/字节数）
6. **跑失败路径**：破坏前提（如删掉假 OBS），断言 EXIT=1 + 明确错误信息

## 速查

```
沙盒 = 镜像目录 + 假目标目录 + 环境变量重定向 + 进程名打补丁
成功路径断言 EXIT=0+产物；失败路径断言 EXIT=1+错误信息
```

## 预防

- 验证脚本只测安装逻辑，不测真实环境副作用——真实写入留在用户自己确认后跑
- 沙盒目录用完删掉（在项目 `_runtime/` 内，不进版本库）
