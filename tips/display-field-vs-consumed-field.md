# 被程序消费的字段不能直接拿来做展示与翻译

## 现象

面板上 11 个技能的“用途”是英文，需求是“面板无论如何都要全中文”。最自然的做法是把技能文件 `SKILL.md` 的 `description` 翻成中文——改一处，面板、Agent 清单、详情页三处同时变中文，看起来最省事。

实际评估后否掉了：`description` 不是给人看的用途，它是**给模型的路由指令**。翻译它等于改行为，而且没有验收手段。

## 根因

同一个字段被两个受众消费：

| 受众 | 字段 | 决定什么 |
|---|---|---|
| 人 | 面板用途 | 一眼看懂这个技能干什么 |
| 模型 | `SKILL.md` 的 `description` | 什么情况下触发这个技能 |

把展示层直接绑到控制字段上，于是"改显示"必然变成"改行为"。具体损失：

1. **丢英文触发词**。描述里是 `Use when the user asks to visualize system architecture, infrastructure, cloud/security/network topology...` 这类触发条件，翻成中文后英文提问不再命中。
2. **破坏写在描述里的互斥路由**。例如 `矩阵图文发布` 那条写着「触发互斥：含"做/生成/生产"意图 → 进化猫图文流水线，非本 Skill」；翻译走形就会路由错。
3. **改动不可验收**：改完谁来判断触发率变好还是变坏？

## 修复/步骤

拆成两个字段，各管一个受众：

- **面板用途 = `summary`**（可选覆盖字段，存在面板自己的状态里）。填了就显示它，没填就回退到技能文件原文。面板要全中文 → 只填这个。
- **技能文件 `description`** 保持原文，永不为了显示去动它。
- 详情页把两层**分开**展示：先给面板用途，当它与原文不同时，再用独立只读区块列出「技能文件里的用途原文」，调用名归来源信息——人要核对的都在，但不混进表单流。

本次落地：为 11 个纯英文/英文主句起头的技能 + 6 个平台内置共 17 条写入 `summary`，面板 76 个技能的用途全部中文，**技能文件一字未改**。

## 预防

- 设计展示层前先问一句：**这个字段有没有被程序或模型消费？** 被消费的字段不参与展示文案与翻译。
- 用户说"面板要全中文"时，先确认要改的是**展示**还是**控制**；把两者绑死的设计要主动拆开，而不是照着字面去翻译。
- 真要让 Agent 也按中文理解，应写成「中文说明 + 保留英文触发词」并逐条验证触发效果——单独立项，不混在展示整理里做。
