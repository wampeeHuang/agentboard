# 过滤芯片的数字必须和实际点击结果一致
type: diagnosis
date: 2026-08-05
source: source-rack 用户反复报 bug——域名芯片写 46，点击显示 89 行；选档位后无关域名变 0

## 现象
用户点击域名芯片"开发工具"（显示 46），实际筛选出 89 行。选 S 档位后电商/商业等芯片变 0，用户以为数据丢了。

## 根因
芯片计数和筛选匹配用了不同规则：
- 芯片计数只算 `_primary`（主一级）：46 个源的 primary 是开发工具
- 筛选匹配检查 `data-domain` 的全部值（primary + secondary + crossTags）：89 个源因为 crossTags 也命中

两者不一致 → 用户看到的数字不等于点击后的结果 → 信任崩塌。

第二个问题：筛选后动态更新芯片数字，不相关的变 0 → 看起来像 bug 而不是"此档位下没有"。

## 修复/步骤
1. 计数规则对齐筛选规则：domainCounts 也计入 crossTags
2. 芯片始终显示全局总数，不随筛选变动（和档位/类型芯片行为一致）
3. 验证：每个芯片的数字 = applyFilters(domain=该芯片).length

## 预防
任何带芯片筛选的 UI，上线前跑自动化对比：所有芯片的数字 vs 点击后的实际行数。不一致就报错。
