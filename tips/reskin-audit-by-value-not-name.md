# 换皮后审计颜色按值不按名：类名/变量名是历史标签，真值在定义处

## 现象

vivi-design-system 从旧品牌换皮后，实渲染成"绿墨白"，品牌黄 `#D9E26B` 缺席。按类名/变量名逐处排查都是"黄色"该对，但一渲染就错。最后按**值**扫描，发现 5 处同类脱钩：

- `:root` 里 `--yellow: #262B27`（变量名黄、值是墨）
- `.hl-yellow { background: rgba(38,43,39,0.4) }`（类名黄荧光笔、背景墨）
- `.card-pill--yellow { background: rgba(38,43,39,0.25) }`（类名黄变体卡、背景墨）
- `--blue: #74A63F`（变量名蓝、值是品牌绿）
- `--red: #262B27`（变量名红、值是墨）

## 根因

换皮（reskin）时保留旧品牌（esther 时代 `blue/yellow/red`）的标识符命名，只改值不改名。标识符名变成历史标签，与真实颜色值脱钩。按名审计必然被骗——"`.hl-yellow` 怎么会是墨色？" 名字说了黄，值说了墨，人默认信名字。

同类模式也会出现在 `.cool-btn-yellow`、`:root` fallback（`var(--yellow, #262B27)`）等"类名/变量名是色名但值被换色"的位置。

## 修复/步骤

换皮或改版后，对设计系统做一次**按值审计**：

```
1. 列出品牌契约全部色值（如黄 #D9E26B / 绿 #74A63F / 墨 #262B27）
2. grep 全库每个色值的出现位置，反向归类：
   rg -n "#D9E26B|#262B27|rgba(38,43,39|rgba(217,226,107" references/ assets/ docs/
3. 对每个带色名的类/变量（--yellow、.hl-yellow、*-yellow、--blue、--red），
   核对它的实际值是否等于契约对应色
4. 值≠名 → 修值到契约色（--yellow 改真黄、荧光笔墨底改黄调 rgba(217,226,107,0.4)）
5. 改完再 grep 契约色，确认品牌色在各场景真实出现
```

发现 1 处是巧合，5 处同类 = 系统性腐化，直接改到契约，不逐个凑合。

## 预防

- 换皮后第一件事不是看结构，是**按品牌契约色值全库 grep**，看每个品牌色真实出现几次
- 类名/变量名是历史标签，永远不能当真相源；真值在 `:root` 定义和 rgba/hex 里
- 命名与值冲突：值对名旧 → 标记或重命名；名对值错 → 立即修值（本案例：类名 `-yellow` 值墨 = 真 bug）
- 配套参考 `delete-css-token-grep-all-files.md`（删/改名 token 的 grep 归零闭环）——本 tip 是"为什么会有漏网之鱼"的认知根因，那是"怎么清干净"的操作闭环
