# 读者心智模型预检：Use vs Build

type: pattern
date: 2026-08-10
source: 2026-08-10-graph-engineering-wiki 复盘

## 现象
面向架构师的内容写成面向用户的 App 推荐指南，反之亦然。用户反馈："你给的是如何去用别人的应用，但我更想倾向的是如何去搭建出这些框架来"。

## 根因
AI 默认从"怎么用"组织信息，因为互联网上 90% 的技术内容都是 how-to-use。不区分读者是来"用现成方案"还是"学架构自己搭"——两个方向的信息结构完全不同。

## 修复
动笔前先回答一个二进制问题：
- **Use**：读者要选个框架直接上手 → 选型对比 + 上手路径 + 踩坑指南
- **Build**：读者要学设计模式自己搭 → 架构拆解 + 解耦分析 + 借鉴方向

标题本身应暗示视角。Use 型标题："XX 选型指南"。Build 型标题："XX 架构设计——怎么搭自己的"。

## 预防
接到文档任务时，第一个确认问题：读者看完是用还是搭？不确定就问用户——这一问省三轮返工。
