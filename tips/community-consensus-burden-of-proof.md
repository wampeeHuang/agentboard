# "社区共识"是断言，不是观察

## 现象
Agent 看了 8 个 GitHub 个人仓库（最高 24 星），在概念页写下"社区共识是……"。用户追问后发现：没有机构背书、没有大规模采用、没有独立交叉验证。所谓"共识"= Agent 在搜索结果里看到了几个相似内容→自行归纳为共识。

## 根因
"社区共识"在 Agent 认知中是描述性短语（"我看到好几个都这样写"），在读者认知中是规范性断言（"这是被广泛认可的标准"）。Agent 没有感知到这个语义鸿沟。

"社区共识"的证据门槛：
- 机构背书（Linux Foundation、W3C、IETF 级别）
- 或：独立项目 ≥ 50 + star ≥ 1000 的代表性仓库
- 或：行业报告/学术论文明确记载

三个全不满足 → 只能写"多个独立项目采用以下模式"，不能写"社区共识"。

## 修复
用"多个独立项目不约而同采用"替代"社区共识"。前者可验证（列出项目即可），后者是推测（需要证明"足够多人"= 共识）。

更一般地：声称共识 = 承担举证责任。没有机构背书或大规模采用数据 → 降级为"观察到的模式"。

## 预防
- grep 概念页草稿中的"共识""标准""最佳实践""行业做法" → 逐条验证是否有独立权威来源支撑
- 没有 → 替换为可验证的描述（"N 个项目采用了"、"X 标准定义为"）
- 自问：反方会认同这是"共识"吗？不会 → 不写共识
