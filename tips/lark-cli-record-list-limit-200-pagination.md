# lark-cli 读表单次硬上限 200：超出静默丢数据，必须循环 offset 分页

## 现象
表已有 205 条，用 `lark-cli ... +record-list --limit 200` 只取回 200 条。当日新增的 3 条候选（第 201+）不可见。下游三处症状：校验误报"记录不在表中"、状态面板漏显示待发布状态、写入靠另一路兜底才没炸。

## 根因
`+record-list` 的 `--limit` 有 200 硬上限，传更大值也不会取回更多。超出部分静默缺失——不报错、不警告，调用方以为拿到了全表。

## 修复/步骤
循环分页，直到返回短页：
1. 从 offset=0、page_size=200 开始
2. 每次取回后检查行数：`len(rows) < page_size` 即到底，break
3. 否则 `offset += page_size` 继续
4. 加页数硬上限（如 20 页 = 4000 条）防无限循环

## 预防
- 任何"读全表"的调用，先确认表可能的最大规模，别信单次 limit
- 分页循环必须带退出条件（短页判断）和页数上限
- 静默截断是最危险的失败模式——宁可报错也别让下游以为数据完整
