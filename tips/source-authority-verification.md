# 信源权威性：星数/作者/机构三重验证

## 现象
Agent 把多个 GitHub 个人仓库（24 星、匿名作者）的内容归纳为"社区共识"，写在概念页中作为定论。用户指出后才验证——发现真正的权威来源是 Linux Foundation、GitHub 官方博客，而这些在初始搜索中完全被忽略。

## 根因
Agent 搜索策略是"找匹配内容"，不是"找权威来源"。看到一个 repo 内容对得上 → 直接引用，不追问"谁写的、多少人用、有没有独立验证"。

## 修复
信源入页前三问：
1. **谁写的** — 个人还是机构？能查到名字吗？
2. **多少人用** — stars/downloads/adoption 数据？
3. **谁验证过** — 有独立第三方引用吗？还是自己说自己的？

三个全过 → 可标"权威"。过一个 → 如实标"有限信源"。全不过 → 只能当草稿/推测。

## 预防
- 概念页声称"社区共识"、"行业标准"前，必须找到机构背书或独立交叉验证
- GitHub 仓库默认视为"个人项目"，直到证明有机构归属或广泛采用
- agentpatterns.ai 类匿名网站：内容有用，但不能当一手权威
