# 聚合层词表失配：数据静默丢失而非报错

## 现象
- 上游快照写 `worst: "error"`，下游面板词表是 `fail` / `warn` / `pass`
- 三个 error 级项目在总览计数、筛选条、分组页**全部不可见**——不是显示错误，是不显示
- 控制台零报错：字符串不相等只是 `false`，不炸

## 根因
两个系统各自定义状态词表（executor 判定层用 `error`，展示层用 `fail`），聚合边界没有归一层。`p.latest.worst === 'fail'` 对 error 永远 false → 条目从所有计数和筛选里静默蒸发。

危险点：**这类 bug 没有失败信号**。UI 照常渲染，只是少了几条。只有对照原始数据才能发现"少了"。

更阴的二次坑：主渲染处修了归一（`worstOf()` 函数），**手写副本没修**——说明书页的活数字注入是一份独立手写的比较逻辑，同款失配又存活了一轮。修一处不等于修一类。

## 修复
聚合边界统一归一函数：

```javascript
function worstOf(p){
  if (!p.latest) return 'na';
  var w = p.latest.worst || (p.latest.ok ? 'pass' : 'fail');
  return w === 'error' ? 'fail' : w; // 上游词表 error → 本层词表 fail
}
```

然后 grep 下游全部消费点（`worst`、`=== 'fail'` 等字面量），每个手写比较处逐一核对是否走归一层。

## 预防
- 跨系统聚合（日志→快照→面板、API→前端）先对齐**两端状态词表**，在边界处归一，不指望上游迁就下游
- 归一逻辑写成函数/常量表，禁止每个消费点手写字面量比较——手写副本是隐形契约，必漂移
- 验证词表类 bug：拿一条上游真实数据（如 error 态项目）对照下游计数是否 +1，数字断言程序验证
