# bash 里带方括号的 HTML 正则触发治理器误判 → 用 Grep 工具替代

## 现象

bash 里跑 `grep -E '<blockquote|<table[^ >]' index.html` 这类含方括号 `[...]` 的 HTML 标签正则时, 治理器 hook 报"工作区治理器已阻止结构性写入", 命令被拦下。实际只是想查询, 不是写入。

## 根因

治理器 hook 解析命令时, 把 `[^ >]` 这类正则片段的方括号误当成路径/glob 片段解析, 判定为可疑的结构性访问。括号越重(字符类、区间)越容易误命中。这是 hook 的正则解析缺陷, 不是命令本身危险。

## 修复/步骤

查询 HTML 里的标签/括号正则, 改用 **Grep 工具(rg)** 而不是 bash grep:

```
Grep 工具: pattern='<table[^ >]'  →  rg 原生支持, 不经过治理器命令解析
```

Grep 工具是对 rg 的封装, 走独立权限通道, 括号正则原样传递, 不被 hook 当路径片段解析。输出内容/计数/上下文模式全覆盖(bash grep 能干的它都能干)。

## 预防

- 凡要搜含 `[` `]` `{` `}` 的 HTML/CSS/JS 模式, 一律 Grep 工具, 不写 bash grep
- 纯文件名/路径的查找也优先 Glob/Grep 工具, 减少 bash 里触发治理器误判的机会
- 被拦时先想"是不是查询该换工具", 不要加引号/转义硬闯——误判是工具选择问题
