# 用户项目不作测试夹具，估算边界不作破坏性裁剪

## 现象

内容生产应用既要验证保存、覆盖、删除、恢复和音频关联，又保存着用户唯一的项目数据。若自动化测试直接复用当前项目，测试即使通过，也可能覆盖稿件、音频关联或项目索引。录音场景还有第二层风险：界面能估算句子时间，不代表能据此安全裁剪真实录音。

## 根因

1. 把“服务入口可访问”误当成“真实项目可作为测试环境”。
2. 把显示序号当稳定身份；增删一句后，序号会整体变化。
3. 把文字权重产生的估算句界当成真实音频切点。
4. 只验证成功路径，没有验证部分覆盖、改稿失配和删除锚点。

## 修复

1. 自动化测试必须创建独立临时项目根，并在测试结束后清理；真实 `projects/` 只做只读页面和接口核验。
2. 录音绑定不可变句子 ID + 正文快照，显示序号只负责呈现。
3. 真实音频长度决定片段总长；没有强制对齐证据时，片段内句界必须标为估算。
4. 新范围完整覆盖旧片段时可以替换；只与旧片段部分重叠时先拒绝，不按估算时间静默裁剪。
5. 覆盖验证至少包含：范围落盘、试听、解除关联、重录、恢复、静音保护、前插句后锚点稳定、改稿失配、删除锚点进入未使用状态。

## 预防

任何拥有用户草稿、媒体或生成资产的本地应用，在写测试前先回答两问：测试根是否与用户数据物理隔离；所有 destructive-like 行为是否基于可证明的精确边界。任一答案是否定，就先补隔离或拒绝危险操作，不用“测试后恢复”作为保护策略。
