# 按钮文案用动作动词，不描述结果状态

---

## 现象

按钮文案："✓ 确认已办：社保费扣款 8/2截止"。用户反馈：还没点，按钮就说"已办"——按钮在替用户宣告结果。

## 根因

AI 写按钮标签天然倾向描述状态（"确认已办""提交成功""已删除"），但按钮是动作入口，属于 Norman 模型的 execution 侧，不是 evaluation 侧。按钮文案必须回答"点我会发生什么"，不是"当前是什么状态"。

状态描述型按钮的错误心理模型：用户看到"已办"→ 疑惑"我已经做了吗？"→ 信心下降 → 少点击。

## 修复

```
❌ 确认已办：社保费扣款 8/2截止    （结果状态）
❌ 已申报：增值税 7/15截止         （结果状态）
✅ 标记已办：社保费扣款 8/2截止    （动作动词 + 目标）
✅ 点击确认：增值税 7/15截止       （动作描述）
```

## 检查法

按钮文案去掉 ✓/✗/图标前缀 → 读起来像已完成的状态描述？→ 错了。应该是祈使句或动宾结构。

适用场景：Feishu 卡片按钮、网页 CTA、推送通知 action、确认对话框。
