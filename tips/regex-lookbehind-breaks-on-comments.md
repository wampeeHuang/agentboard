# 正则 lookbehind 在分隔符与目标之间夹注释时失配——改用捕获边界

## 现象
CSS 声明迁移脚本用 lookbehind 匹配声明，编译门禁报出 10 处声明没迁移到（如 `--tl-dot:8px` 仍硬编码）。grep 能搜到该属性，但脚本匹配不到。

## 根因
`(?<=[{;}]\s*)([a-zA-Z-]+)\s*:` 假设 `{`/`;` 后面**只有空白**再跟属性名。但 CSS 里 `;` 和下一声明之间常夹注释：
```css
--tl-axis-w: var(--space-24); /* 轴宽 */ --tl-dot: 8px;
```
`/* 轴宽 */` 不在 `\s*` 里，lookbehind 要求"`;` 后紧跟空白+属性名"失配，整条声明被静默跳过。

## 修复/步骤
把 lookbehind 换成**捕获边界 + 显式吃注释**：
```js
// 之前（lookbehind，注释夹在中间就失配）
/(?<=[{;}]\s*)([a-zA-Z-]+)(\s*:\s*)([^;{}]+)/g

// 之后（捕获边界，注释当"可跳过分隔"显式吃进去）
/([{;])((?:\s|\/\*[\s\S]*?\*\/)*)([a-zA-Z-]+)(\s*:\s*)([^;{}]+)/g
// 替换时 ${boundary}${between}${prop}${sep}${val} 原样回填，不丢注释
```

## 预防
用 lookbehind 匹配"前导分隔符"前，先想分隔符和目标之间可能出现什么**非空白 token**：注释、BOM、转义、`@` 规则前缀。
- lookbehind 无法表达"任意可跳过的中间内容"，遇到就换捕获边界
- 任何 CSS/JS 文本解析脚本，注释处理要放第一步，不能假设"注释不存在"
- 迁移类脚本要**幂等 + 全量审计**：跑完用门禁反查"还有没有漏网的硬编码"，靠门禁兜底而不是靠正则一次全中
