# 移动页面后必须枚举它引用的**全部**相对资源；验证脚本的失败监听要覆盖新标签页

## 现象
把 `README.html` 从仓库根移到 `docs/manual/index.html`（文件名同时改成 index.html）。
搬完后我的验证脚本 11/11 全绿，其中包含"全程无 4xx/5xx"。用户一打开页面就发现：
**整页没有颜色、页面上的 mark 图不显示。**

复现（把监听挂到 context 而不是单个 page）：

```
404  /docs/manual/vendor/vivi/vivi-tokens.css   ← 规则数 0，--green 为空，body 背景透明
404  /docs/manual/favicon.svg                   ← <img> 尺寸 0x0
```

## 根因（两个独立缺陷叠在一起）

**① 移动文件后只改了"我碰过的那几处"引用，没枚举全部。**
新位置深了两级，页面里三条根相对引用都要退两级：
`./vendor/vivi/vivi-tokens.css` → `../../vendor/…`、`favicon.svg`（`<link rel=icon>` 与 `<img mark>` 各一次）→ `../../favicon.svg`。
我当时只处理了 `diagrams/x.html`（那是我刚搬过的），其余引用从未列过——
**因为 `<link>` 与 `<img>` 静默失败**：浏览器不报错、页面不白屏、控制台只有一行 404，
不像 JS 异常那样显眼。结果就是"难看但不报错"。

**② 验证脚本的失败监听挂错了范围，于是报了假绿。**
脚本里 `page.on('response', …)` 挂在**应用页**上，而说明书是 `target="_blank"` 打开的**新标签页**：
它的资源请求完全不在监听范围内。于是"全程无 4xx/5xx"这条断言永远为真——
**断言本身是坏的，比没有断言更危险**，因为它给了一个"已验证"的错觉。

这与本轮其他几次是同一个病根：**作用域选错**（跨项目误伤 / 口径太窄 / 只搜三个文件就断言零引用 /
这次是"只监听一个页面"）。

## 修复/步骤
1. 源文件引用退两级；构建脚本（发布副本是扁平的）把这两级再退回去，
   并对每个重写加**数量断言**（favicon 2 处、vendor 1 处、diagrams 4 处）——
   路径将来再变时，构建会直接失败而不是静默产出坏站。
2. 验证脚本改三处：监听挂 `context`（覆盖它开出的所有页面）；
   加"资源真的加载了"的断言——**不只数状态码**：
   - 外部样式表 `cssRules.length > 0`（404 的 CSS 规则数是 0）
   - `getComputedStyle(root).getPropertyValue('--green')` 非空、`body` 背景不是透明
   - 页面 `<img>` 的 `naturalWidth/naturalHeight > 0`（404 的图是 0×0）
3. 发布副本单独核一遍：解析构建产物 HTML 里的全部相对引用，逐个断言文件存在。

## 预防
- **移动/重命名页面后，第一件事是枚举它的全部相对引用**（`src|href|url(` 三类都要扫，
  含 `<link>`、`<img>`、CSS 里的 `url()`、iframe、以及脚本里的字符串路径），不要只改"我记得改过的那几处"。
- **视觉类资源失败是静默的**：CSS/图片/字体 404 不会抛异常。凡是"页面能打开但样子不对"，
  先做一次全量失败请求体检，再谈布局与色值。
- **验证脚本里凡是要监听"整个流程"的事件，挂 context/全局，不要挂单个 page/tab**。
  只要流程里有 `target="_blank"`、iframe、worker，挂单页就等于没监听。
- 断言要落在**结果**上而不是**中间信号**上：状态码只是信号，"样式表有规则、图有尺寸、令牌有值"
  才是结果。只断言信号时，一个作用域错误就能让整条断言退化成恒真。
- 反过来说：一条**永远为真**的断言与一条**永远为假**的判据是同一种病（本轮两种都踩过），
  加断言时顺手问一句"它在什么情况下会红"——答不出来就是没在验证。
