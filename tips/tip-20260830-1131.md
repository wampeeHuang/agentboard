# Docker 服务恢复先保数据卷，再重建容器与工具登记

## 适用

已存在的 Docker 服务有可保留的数据卷，但容器停止、端口映射缺失、旧配置不可靠，且需要恢复为可被工具架控制的本地服务。

## 步骤

1. **只读确认现状**：检查容器镜像、命令、环境变量名、挂载、重启策略、端口映射和数据卷内文件属主；旧日志只作为线索，不直接当根因。
2. **先复制并校验数据卷**：创建独立备份卷，用只读源卷复制；至少校验关键数据库文件哈希和文件数量。
3. **保留旧容器作为回退点**：停止状态下改名保留，不删除。这样新容器失败时，可停止新容器并恢复旧名称。
4. **以原镜像和原数据卷创建新容器**：只补必要的端口映射和重启策略；本机服务优先绑定 `127.0.0.1`，不要默认暴露局域网。
5. **先健康检查，后登记可用**：确认健康端点、编辑器页和已有工作流都可访问，再把工具架 manifest 补成端口、打开地址、启动/停止命令和启用状态。
6. **记录运行时限制**：例如缺少 Python runner 时，写入工具 `agent_notes`，避免后续 Agent 把“服务已启动”误判成“所有节点都能运行”。

## 为什么

容器、数据卷和工具登记是三件不同的事：重建容器通常不会损失命名卷数据；工具架卡片只有在端口和健康检查真实通过后，才应显示为可启动/可打开。先登记后验证会制造“卡片可见但服务不可用”的假状态。

## 边界

- 不适用于无数据或可从声明式部署完全重建的服务；此时直接重新部署更简单。
- 不要在未备份前修改权限、升级镜像或删除旧容器。
- 有外部数据库、密钥文件或复杂反向代理时，必须同时保留并核对这些依赖，不能只复制 Docker 卷。
