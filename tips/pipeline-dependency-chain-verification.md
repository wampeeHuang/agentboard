# 管线阶段排序：依赖链断裂在图上不可见

## 现象

管线阶段顺序"判→搜→构→写→审→发"视觉上看起来合理。但用户追问："没有搜索如何做出判断？"

排查发现 Stage 1（判断）的 kill-gate 四问（认知税、洞察值、分享货币、平台合规）——前三个需要搜索到的事实/数据/案例才能评分。Agent 在没有任何外部信息的情况下被迫"盲判"。

## 根因

管线图按直觉惯例排序（"先判断再搜索"听起来对），而非追查阶段之间的实际输入依赖。

每个阶段都需要回答一些"问题"。回答这些问题需要数据——如果数据来自下游阶段、当前阶段还没拿到，就是依赖链断裂。

**判断不是凭空产生的——判断是信息加工的结果。** 信息没到，判断就是瞎猜。这是设计层面的依赖错位，不是实现 bug。

## 修复

1. 重排阶段顺序：**搜→判₂→构→写→审→发**（搜索先行，判断基于搜索结果）
2. 平台合规从 kill-gate 四问中拆出，降级为 Stage 1 轻量预检（非阻断）
3. 判升级为判₂（知情判断），trigger 改写为"基于搜索素材做知情判断"

## 预防

设计或审查管线时，四步验证法：

1. 列出每个阶段需要回答的**问题**（不是任务名，是问题）
2. 对每个问题追问：**回答它需要什么数据？**
3. 检查这些数据**来自哪个阶段**——必须在本阶段之前已产出
4. 数据源在后面的 = **依赖链断裂**，必须重排

检验标准：Stage N 的每一项门禁判断，其所依赖的数据源都在 Stage N-1 或更早。没有一项依赖来自 N+1 或之后。

具体到每条规则：在 pipeline manifest 里标注每条规则的 `depends_on`（数据依赖←阶段）——断裂会在设计期暴露，不会隐形到运行时才发现。
