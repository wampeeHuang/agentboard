# 静态站部署：目录里「没被引用」的文件照样会被发布

## 现象

官网部署完成后，15 个页面全部正常。顺手逐 URL 探了一下**不该公开的资产**，结果：

| URL | 状态 | 应该 |
|---|---|---|
| `/assets/img/certs/trademark-14260421.jpg` | **200** | 404 |
| `/assets/img/certs/trademark-14260442.jpg` | **200** | 404 |
| `/assets/img/待确认/A14-检测台候选/1836.jpg` | **200** | 404 |
| `/assets/img/交接-待用户选图/产品主图对号/1742.jpg` | **200** | 404 |

商标件是用户**明确决策不对外展示**的东西（站点代码里确实没有引用它，`slots.json` 也标了「移出 public」）——但因为文件还躺在部署目录里，静态托管会把它当普通文件一起发出去。

## 根因

两件事叠在一起：

1. **静态托管的语义是「目录即站点」**：只要文件在部署目录内且没被 ignore，URL 就可达——**跟页面有没有引用它无关**。代码层「不渲染」根本挡不住直接访问 URL。
2. **`.vercelignore` 只列了构建脚本目录，没列资产池**：写了 `_brand-build/`、`redesign/` 这类"明显不该发"的目录，却漏了「素材池/候选图/内部凭证件」这类**看起来像正常资产**的目录。

## 修复

```gitignore
# 合规：用户决策不对外展示
assets/img/certs/trademark-*.jpg
# 素材池：已选定的图已复制到 placed/，这些是候选与交接区
assets/img/待确认/
assets/img/交接-待用户选图/
```

重新部署后逐 URL 复验：不该公开的 5 个全部 404，应公开的 6 个全部 200。

## 预防

**把「暴露面核查」做成部署流程的固定一步，而不是靠自觉。** 具体：

1. 部署后**逐 URL 探测**三类清单：`不应公开`（期望 404）、`应当公开`（期望 200）。脚本见本机 `_logo-output` 项目里的 `check-exposure.js` 模式——两个数组 + 状态码断言，10 行搞定。
2. 探测**必须真的发请求**。`ls` 目录、读 `.vercelignore`、看 HTML 有没有引用，都不算验证（这次三个都"看起来对"）。
3. 清单来源要覆盖三类容易漏的：**合规件**（未注册商标、未取得证书）、**素材池/候选区**（原始照片、待选图）、**内部资料**（台账、报价、README）。
4. 反面参考：本机已有 `vercelignore-vs-gitignore.md` 讲「.vercelignore 独立于 .gitignore」的机制；**本条补的是另一半——写对了机制，仍可能漏列对象，所以必须按 URL 验证结果**。

## 边界

- 只删 ignore 规则不行：文件要留在本地（`slots.json` 仍引用、将来可能启用），所以用 `.vercelignore` 排除而不是删文件。
- 若站点改用其它静态托管（Netlify/CF Pages/EdgeOne），排除规则文件名不同，**但「按 URL 验证暴露面」这一步不变**。
