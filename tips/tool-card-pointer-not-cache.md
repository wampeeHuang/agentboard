# 工具卡指路不存缓存——真相源在官网，本地副本必漂移

type: method
date: 2026-08-12
source: MD3 工具卡写了 Token 缓存表 + 全尺寸截图，用户连问"这个为什么要放？"

## 现象
写工具卡（type: tool）时，Agent 默认把工具的核心数据复制进卡片——MD3 的颜色 Token 表、参考网站的整页截图。用户反问："核心 Token 这个为什么要放？""这是 md 能解决的吗？它本来是怎么用的？直接网站调用。"

## 根因
混淆了 wiki 的两种类型：
- **工具卡（tool）**：真相源在外部（官网/API/工具本身）。卡片是"指路牌"，回答"是什么、解决什么问题、入口在哪、怎么用"。
- **知识库（参考/概念）**：真相源在 wiki 里。内容才值得完整落盘。

工具卡里缓存 Token 表 = 建立第二个真相源。工具本身一更新，缓存就漂移，读者分不清"哪个是真的"。和"放着原工具不用去抄一份笔记"是同一个病。

## 修复
工具卡只写四样，不写会过期的数据：
1. 是什么（一句话）
2. 解决什么问题（场景驱动，业务语言）
3. 入口（URL 表，做成可点链接）
4. 怎么用（带具体场景的步骤）

会过期的数据（色值、Token 表、API 字段、整页截图）一律不存。需要时 WebFetch 官网现查。截图压成 16:9 缩略图（几十 KB）才放。

## 预防
写工具卡时逐条自问："这个内容半年后还准吗？"
- 会过期 → 删掉，只留 URL
- 不会过期 → 才落盘

判断标准：真相源在外部 = 指路牌，真相源在本地 = 知识库。
