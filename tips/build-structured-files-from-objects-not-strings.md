# 用字符串拼装 JSON/HTML：中文引号、裸换行、百分号的三连坑

## 现象

同一次会话里，用字符串拼接生成结构化文件，连续踩了三个坑，每个都让产物或流程当场坏掉：

1. **中文引号混进 Python 字符串**（发生 **4 次**）。中文写作习惯用 `"` 强调，写进 `"..."` 定界的字符串里就变成提前闭合：
   ```python
   print("...偏离 14.5°，是偏黄的"金"，不是"铜"")   # SyntaxError
   ```
   4 次里有 1 次是"编辑后未重新编译"，导致后续两次都基于坏文件运行。
2. **列表 join 拼 JSON，把裸换行写进字符串值**。为了可读性把一句长文案拆成两个列表元素，
   用 `"\n".join(...)` 拼起来 → JSON 字符串值里出现真实换行 → `json.load` 报
   `Invalid control character at line 79`。
3. **`%` 与格式化字符串冲突**。手工拼的 HTML 模板同时用了 `%s` 占位与 `%%` 转义，
   而 CSS 部分不是格式化字符串不需要转义——同一份文件里两种规则并存，必然搞混。

## 根因

把"文本"和"结构"混在一层里表达。只要数据里可能出现与语法同形的字符
（引号、换行、百分号、反斜杠），字符串拼接就必然出错，而且出错位置离原因很远。

## 修复/步骤

**按产物类型选生成方式：**

| 产物 | 正确做法 |
|---|---|
| JSON | 构造 `dict` → `json.dump(obj, fh, ensure_ascii=False, indent=1)`。**永不拼字符串** |
| 配置/YAML | 同上，用库序列化 |
| HTML（含大量中文文案） | 模板与数据分离；文案放进列表/字典，用 `.format()` 或 `str.replace` 注入**占位符**；模板本身不做 `%` 格式化 |
| 需要动态生成的长文本 | 用列表收集行，最后 `"\n".join(lines)`；**每行是完整的一行**，不要把一个句子拆到两个元素里 |

**额外纪律：**
- 中文里的强调引号一律用 `「」`，不用 ASCII `"`。
- 改完 Python 文件**立刻编译一次**，再做别的：用 `py_compile`（注意**不要传 `quiet`**，见 `pycompile-quiet-swallows-error.md`），或用 `python -c "import ast; ast.parse(open(f,encoding='utf-8').read())"`。

## 预防

- **判据：如果产物有 schema，就用数据结构生成，不用字符串。** 只有纯散文才允许字符串拼接。
- 拼 HTML 模板时，先决定"这份模板走不走 `%` 格式化"，然后整份统一；混用必错。
- 生成后立刻回读校验（`json.load` / 浏览器打开），**"脚本没报错"不等于"产物合法"**。
- 一有中文长文案 + 字符串拼接的组合，就默认高危。
