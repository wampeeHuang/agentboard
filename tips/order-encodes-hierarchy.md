# 顺序即层级：排列顺序承载语义关系

## 现象
Agent 将四条核心原则随机排列——入口文件、元数据、边界权限、LLM Wiki 模式。用户指出 LLM Wiki 是架构基础，放末尾像附录。顺序本身在说谎：把基石放最后 = 暗示它最不重要。

## 根因
Agent 把列表当集合（元素平等，顺序无意义），不当序列（顺序 = 关系）。读者天然认为先出现的重要、先出现的被后面的依赖。顺序是隐式语义通道——用错了传递错误信号，用对了不需要任何标签。

## 修复
排列顺序 = 编码关系。常用递进模式：
- **基础 → 表层**：先定义空间，再定义空间内的规则
- **因 → 果**：先讲原因，再讲结果
- **输入 → 输出**：先讲前提，再讲结论
- **高频 → 低频**：先讲常用的，再讲边缘的

选一种模式，贯穿到底。混用模式 = 读者困惑。

## 预防
- 列完要点后问：如果只能保留前两条，我保留的是最重要的吗？不是 → 调顺序
- 相邻两节之间有依赖关系吗？A 必须成立 B 才有意义 → A 必须在 B 前面
- 检查首尾：第一节像入口、最后一节像终点吗？
