# 视觉 LLM 目检细纹/细线：先做元素级裁剪放大，全页截图会误报

## 现象

把整页截图丢给视觉模型（MiniCPM-V 等）判纹理/细线细节，三种不同图案（点阵、网格、斜纹）被全部读成"点阵"。差点据此以为纹理没改对。

## 根因

整页截图（如 1440×1100）在视觉模型的输入分辨率里，16px 间距、1px 细线的图案被降采样到不可辨——细节低于模型的判读分辨率，模型用大面积特征"猜"内容，于是看什么都像点阵。

## 修复/步骤

细粒度图案目检前，先截出目标元素、放大再喂给视觉模型：

1. CDP 里 `scrollIntoView` 定位目标元素（含父节/区块）
2. 用 `getBoundingClientRect` 拿元素矩形
3. `Page.captureScreenshot` 带 `clip`（元素矩形）+ `scale: 2`（2 倍放大），存 PNG
4. 把这张元素级截图喂视觉模型，问具体图案区分度（点/网格/斜纹各自可辨？）

## 预防

- 判"某种图案/细线存不存在、长什么样"一律先裁元素再目检；全页缩略图只够判布局与崩坏，不够判细节
- 视觉模型对细节的误报不可信到会误导方向——当它说"全都一样"时，先怀疑截图精度，不是先改实现
