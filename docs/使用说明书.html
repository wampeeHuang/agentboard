Cards

工具架页：一张卡片一个工具

打开就是卡片。状态、冲突、盲区，全写在卡片上。四个筛子切维度，一个搜索框找名字。

Filter · 1功能模型 / 语音 / 浏览器 / 文档…
Filter · 2部署位置本机 / 局域网 / 云端
Filter · 3访问方式MCP / API / 网页
Filter · 4状态运行 / 停止 / 出错 / 警告

「治理审计」是独立一页，四合一巡检怎么读，见第 05 节。

卡片怎么读
示例工具● running

一行能力描述：这个工具能干什么，一句话讲清。

CONFLICTS无 — 可安全启动
AGENT NOTES异步两阶段，确认收到 prompt_id 再等结果
1
状态，不是「看起来在跑」

三段验证：端口活？PID 文件对得上？进程真活着？全过才算 running。灯亮不算数，验证账本才算。

2
conflicts · 谁跟它打架

GPU 显存互斥、端口冲突，都记在这里。冲突的工具在跑，先停再启动，或换方案。

3
agent_notes · 模型的盲区

AI 容易在哪儿踩坑，逐条记着。动手前对照自己的操作计划，别踩中已知坑。

4
启停

没跑就启动，在跑就停止 / 打开。启停走 PID 精确杀进程树，不留孤儿。

状态靠验证账本，不靠灯亮

端口活跃 ≠ 工具在运行。以 PID 身份凭证为准，拒绝「看起来在跑」。

04
Operate

你看着，AI 调

人在面板看，AI 走 MCP 调。同一张卡片，两边读。

AI动手前，先查架
1
查工具

在清单里找到目标工具。

2
读冲突

谁跟它抢显存、打架。冲突的工具在跑，先停或换方案。

3
读盲区

对照 agent_notes，检查自己的操作计划有没有踩中已知坑。

4
看状态

没跑就启动，在跑就直接调。

你装完新工具，写清单即注册
1
写清单

写 manifest：是什么、怎么启停、跟谁冲突。写进去就校验——字段不合规、端口被占，当场拒绝。

2
上架即见

写完就上架，下次请求自动重扫，不用手动确认。

装了不写 = 白装

不注册，工具在架上不可见，AI 发现不了、调不了。清单是唯一真相源，架子只看它。

05
Audit

治理审计：三态巡检，一眼看清

manifest 契约 / 品牌漂移 / 三树一致性 / 文档新鲜度，四项各一块。总面板先给数——正常、警告、错误各多少，点数字只看该类。

Check · 1Manifest 契约一张卡一个 manifest · 字段 / 端口 / 冲突 / 孤儿目录
Check · 2品牌漂移黄绿白 / 标题字体 / token 契约值集
Check · 3三树一致性AGENTS.md / README / 说明书 声明树 vs 磁盘
Check · 4文档新鲜度页面清单 / 页数 vs 真实导航 PAGES
看四项怎么读
1
总面板

正常、警告、错误三条数——点数字只看该类，先看有没有红。

2
分块

每项一块，块头显示该项 N 项 · X 错误 · Y 警告。

3
条目

先项目名，再错误，再警告，最后正常。黄是警告，红是错误，绿是正常。

修异常即清单
1
有黄有红

异常项就是该修的地方——红必须修，黄看情况。

2
全绿

三块全绿 = 契约、品牌、声明树都对得上，可以放心改。
