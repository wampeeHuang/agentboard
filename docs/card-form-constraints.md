# 工具表单约束盘点 — 条件 / 互斥 / 因果

> 目标：表单不再「想填啥填啥」。每个字段的显隐、必填、互斥、自动，全部由一张约束表驱动。
> 数据依据：66 manifest 实测字段出现率 + 外部状态卡范式。

---

## 一、类型（主开关，单选，5 值）

| 类型 | 定义 | 谁归这类 | 必填 |
|---|---|---|---|
| **服务** service | 常驻后台进程（含本地 API 服务） | 模型（本地）、Supervisor、画廊… | startCommand 或 port |
| **命令** cli | 用完就走的一次性命令 | 视频管线、剪藏… | trigger |
| **API** | 外部供应商服务，本地无进程 | 模型（远程）、Coze、Figma MCP… | apiBase |
| **文件夹** folder | 项目目录，不可运行 | workspace 项目 | projectPath |
| **组** group | 多工具编排 | 日报组、视频管线组… | children |

**判断**：原 4 类漏 API。API 是「注册上去就能调」的工具主体（模型-远程 7 个 + 各类外部服务），必须有专属类。分类里模型不再拆本地/远程——运行位置由独立 `loc` 字段承担。

## 二、字段 → 显隐条件（类型驱动）

| 字段 | 显示于类型 | 说明 |
|---|---|---|
| 端口 port | 服务 | — |
| 页面 URL url | 服务、API | — |
| API 地址 apiBase | 服务、API | AI 直接调用入口 |
| API 密钥名 apiKeyName | API | 指向密钥库 |
| 触发词 trigger | 命令 | Claude Code 里 /xxx |
| 启动/停止命令 | 服务、命令 | 服务=起停，命令=执行 |
| 运行时 runtime | 服务、命令 | **下拉**：node / python / bun / deno / … + 自定义 |
| 项目路径 projectPath | 服务、命令、文件夹 | API/组 不需要 |
| 开机自启 autoStart | **服务 且 未停用** | API/命令/文件夹/组 无自启 |
| 停用 disabled | 全部 | — |
| 子工具 children | 组 | 编排子任务 |
| 版本 version | — | **自动显示值，非输入框**（package.json / git tag） |

## 三、互斥 / 因果规则

| # | 规则 | 理由 |
|---|---|---|
| 1 | **停用 disabled ⇄ 自启 autoStart**：停用勾上 → 自启隐藏/禁用 | 停用=AI 不可调，自启无意义，矛盾 |
| 2 | 类型单选，一次一个，全表单跟着变 | 主开关 |
| 3 | **分类 → 类型建议**：选分类自动给默认类型，可改 | 模型→服务/API；获取→API/命令；创作→服务/命令/文件夹；设施→服务 |
| 4 | 运行时下拉，不自由填 | 防拼错，node/python/bun 有数 |
| 5 | API/文件夹/组 → 无 runtime、无启动停止命令 | 没本地进程，填了就是假数据 |
| 6 | 必填随类型变（表一最后一列） | 服务没启动命令=死工具 |
| 7 | 版本自动，用户不可填 | 人工维护必漂移，包管理器有真值 |

## 四、全局必填（任何类型）

- name ≥2 字
- 功能 description ≥10 字，含【用途】
- 分类 category 必填
- 类型相关必填（表一）

## 五、自动计算字段（不落盘或落盘时算）

| 字段 | 来源 |
|---|---|
| version | package.json / git describe |
| form 徽章 | 由类型推导（服务/命令/API/文件夹/组 → 中文徽章） |
| state 状态 | scanTools 运行时算，8-9 态 |
| icon | name 首字（有 icon 用 icon） |
| 【返回】描述段 | 由调用字段自动拼 |

---

## 六、表单区块顺序（重排后）

1. **身份**（名字/ID/版本自动显示）
2. **功能**（这工具干嘛）
3. **分类**（决定类型建议）
4. **调用方式**（按类型条件显示）
5. **何时调用**（何时用/不用）
6. **运维**（路径/运行时下拉 → Agent 笔记 → 自启/停用）
