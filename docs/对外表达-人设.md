# 对外表达 · 人设与铁律

> 给 agent 工具架写对外介绍时，先读本文件。防偏移用。

## 人设（先摆位置）

- **读者**：外部网友 / 潜在用户。不是工程师，不是我自己。
- **目标**：让一个陌生人读完，知道「这能帮我干什么、怎么用」。
- **边界**：只讲「能干什么、怎么用」，不讲「怎么实现的」。

## 脱敏清单（读者不知道、也不需要知道）

| 不能写 | 为什么 | 换成 |
|--------|--------|------|
| 端口号（3099 / 3097 / 3100） | 端口不是网址，会变，外部人无用 | 「面板」「守护」「调度」等角色名 |
| JSON-RPC / Streamable HTTP / REST 传输细节 | 内部传输协议，对外是噪音 | 「AI 通过标准接口调用」 |
| tools/*/manifest.json 等内部路径 | 内部实现 | 「一份清单」 |
| 密钥 / apiKeyName / 环境变量 | 泄露 + 外部人无关 | 不提 |
| lib/ 模块名、PID、进程 | 内部实现 | 「背后有守护机制」 |

## 写每一句前自检

1. **自包含**：陌生人读这句，能懂吗？
2. **脱敏**：这句泄露内部实现了吗？
3. **人话**：有术语吗？能翻成「解决什么问题」吗？
4. **外部视角**：写的是「你能拿它做什么」，还是「我怎么实现的」？
5. **图优先**：这里能画图吗？能画就不写文字。

## 图优先（能图不文）

- **能图表达就不写文字**。架构→架构图，流程→流程图，界面/操作→截图。
- 图片同样脱敏：图里不出现端口、密钥、内部路径、模块名；截图里的内部信息打码或裁掉。
- 图配一句人话（图表达结构，文字点出「这帮你解决什么」），不重复图里已有内容。

## 反面教训（已踩的坑）

- 架构图写 `:3099` `:3097` `:3100` → 端口不是网址，会变，外部人无用。换成角色名。
- 写 `JSON-RPC 2.0 · Streamable HTTP` → 内部协议，对外是噪音。换成「AI 通过标准接口调用」。
- 写 `tools/*/manifest.json` → 内部路径。换成「一份清单」。

## 上下文提示词（每次开工先读这段）

> 我在给 agent 工具架写对外介绍。读者是外部网友，不是工程师。
> 只讲「能干什么、怎么用」，不讲「怎么实现」。
> 禁止暴露：端口、密钥、内部协议、内部路径、模块名。
> 每一句写完自问：陌生人能懂吗？有没有泄露内部实现？
